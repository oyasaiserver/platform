# `/sldata dialog` グラフ形状のソースオブトゥルース

新しい指標を追加するとき、**どの「形」を選ぶか**の判断基準と、各形の実装パターンをここに集約する。 **実装前に必ず読むこと。**

文字・フォント・配色の細則は [DIALOG_STYLE.md](DIALOG_STYLE.md) を参照（ここでは重複させない）。 設計原則の一次ソースは
Vault `Knowledge/apple-chart-design-framework.md`（Apple HIG、一次ソース確認済み）。
型とカテゴリ分けが決まった経緯は Vault `Decisions/2026-08-15-sldata-chart-design.md`。

---

## 形は5種類

| # | 形 | 実装関数 | 使う場面 | |---|---|---|---| | 1 | 比較表 |
`dialogComparisonTableSection` / `DialogComparisonTableRow` | 2値の比較（あなた vs
全体、送った vs 受けた、前 vs 後） | | 2 | 縦棒グラフ | `dialogStatsVerticalBarSection` /
`buildDialogGraph` | 分布・時系列（1本の軸に沿った値の並び） | | 3 | ヒートマップグリッド |
`dialogActivityHeatmapSection` | 2軸のデータ（曜日×時間帯など、独立した2つの軸を持つとき） | | 4 | ランキング一覧
| `dialogStatsRankingSection` | 人・建築の順位付きリスト | | 5 | 単純テキスト |
`dialogStatsSection`（`List<String>`） | 比較も分布もない、1〜数行で完結する事実 |

### 選び方（決定木）

```
そのデータは...
├─ 2つの値の比較か？（A vs B、前 vs 後）
│   └─ Yes → 1. 比較表
├─ 1本の軸に沿った分布・時系列か？（カテゴリ別件数、月別推移）
│   └─ Yes → 2. 縦棒グラフ
├─ 独立した2つの軸を持つか？（曜日×時間帯のような格子）
│   └─ Yes → 3. ヒートマップグリッド
├─ 順位のついた人・建築のリストか？
│   └─ Yes → 4. ランキング一覧
└─ どれでもない、比較も分布もない単発の事実か？
    └─ Yes → 5. 単純テキスト
```

Apple (WWDC22 110342): 「**新しい形はアプリの中心にあるべきで、補助的であってはならない。**
数値2つで足りるものを図にすると読む手間が増える」。迷ったら軽い形（比較表・単純テキスト）を選ぶ。

## 実例（実機ダンプより、2026-08-17取得）

`/sldata dialog stats2 dump <player>` の出力をそのまま転載。**行頭の `(色名)` / `(#rrggbb)`
はダンプツールが付与する色注記で、実際の画面には出ない。**
ダンプは1行につき1色しか記録しないため、ヒートマップのようにセルごとに色が違うグラフでは、この注記は代表色に丸められている（実際は`⬛`1文字ずつ別々の色）。行同士の**文字の並び・列の整列**は画面と完全に一致する。

### 1. 比較表

```
相互になっている割合
(gray) 説明:片思いか、応え合えているか
(gray) 応援している側　　▁████████████▁１００％ = ７４．２％▁562人中417人
(gray) されている側　　　▁████████████▁　２５％ = １８．７％▁2,228人中417人
```

ラベル列のパディングは全角スペース（`▁`だと日本語ラベルの中で下線のように目立って見えたためユーザー判断で変更、2026-08-17）。
比率(%)は3桁固定・全角スペースで左詰め（"１００％" と "　２５％" が同じ幅になり下の行とズレない）。
バーの比率(%)と実測値をつなぐ記号は半角スペース+`=`+半角スペース。

## 今回のセッション（2026-08-17）で確立した制約

活動リズムをヒートマップ化する過程で見つかった、**今後すべての形に適用すべき**教訓。

### 1. 濃淡は色で表す。文字は変えない

`▁░▒▓█`
のように濃淡ごとに文字を差し替える方式は**やめる**。`░`(U+2591)は他のブロック文字と送り幅が1px違い、混在した列は必ずずれる（実機検証済み、Vault
`Knowledge/minecraft-unihex-advance-width-formula.md`）。

```
✗  ▁░▒▓█  濃淡ごとに文字を変える（送り幅がバラバラで列がずれる）
✓  ⬛⬛⬛⬛⬛  文字は1種類、色だけで濃淡を表す
```

これは [DIALOG_STYLE.md](DIALOG_STYLE.md)
の「横棒で塗り＋アンダーバーをしない」と同じ原則の、2軸グリッドへの適用。棒グラフの「集計途中の当月」も同様に、`░`文字置換をやめて色分けのみ（`incompleteColor`）に変更済み。

### 2. セルには可能な限り hover を付ける

色だけでは正確な値が伝わらない（Apple HIG:
「色は理想的には追加要素として使うのであって、重要な情報を伝える唯一の手段にしてはならない」）。カーソルを合わせると実数値が見える設計を既定にする。

- ヒートマップ: セル1個ずつに個別の
  `hoverEvent`（168個でも問題なく動く。`Component.text("⬛", 色).hoverEvent(hover)`
  を`.append()`で連結するだけ）
- 縦棒グラフ:
  `appendColoredCharsWithHover`（`appendColoredChars`のホバー対応版、2026-08-17新設）で、同じバケットに属する列をまとめて1つのhoverにする

ホバーの1行目は色を付けず灰色固定（`NamedTextColor.GRAY`）。**濃淡はセルの色だけで表現し、ホバーの文字色に重ねて濃淡を付けない**（情報を二重に色で運ばない）。

### 3. 「更新履歴」と「現在値」を混同しない

自己ベストは「今の記録が何か」であって「いつ更新されたかの一覧」ではない。データ構造（更新の履歴リスト）と表示（現在値だけ見せる）は別物として扱ってよい——履歴リストの最後の要素が、そのまま現在値になる。

### 4. before/after の単純比較より、delta同士の比較の方が知りたい問いに近いことがある

「サーバー全体の宣伝後 / サーバー全体の宣伝前」という2本の比較より、「サーバー全体の伸び幅 /
あなたの伸び幅」という**差分同士の比較**の方が、ユーザーが本当に知りたい「自分の宣伝効果は平均と比べてどうか」に近かった（2026-08-17ユーザー指摘で変更）。2値の比較を設計するときは、生の値を並べるべきか、差分を並べるべきかを一度立ち止まって考える。

### 5. 母集団の数字はグラフの実データと必ず一致させる

「対象:
N件」のNは、下に表示される棒やセルの合計と**必ず一致**しなければならない。過去に「サーバー全体の建築数」を、実際にはプレイヤー個人のデータだけを描画しているグラフの母数として表示していたバグがあった（`いいねが付くまでの日数`セクション、2026-08-17修正）。母数を計算する関数は、グラフのデータソースと同じ集合から作る。

### 6. 固定幅のパディング文字は、揃えたいテキストの自然な幅に合わせる

`dialogFixedLabel`のパディング文字は既定で`▁`（5px）だが、**揃えたい対象が全角の日本語ラベルなら全角スペース（`　`、9px）を使う**（ユーザー判断、2026-08-17）。`▁`は視認できる細い線を持つため、日本語テキストの直後に来ると下線のように見えてしまう。パディング文字は「見えない・揃う・元のテキストと違和感がない」の3条件で選ぶ。`dialogFixedLabel`は`fillChar`引数で選べるようにしてある。

同様に、2値比較で並べる数値（%など）は桁数が変わりうるなら**固定桁数で左詰め**にする（全角スペースで埋める）。桁数がそのまま表示に出ると、行ごとに後続の要素（`=`や実測値）の開始位置がずれる。

### 7. 固定幅計算に使う文字は、実測せずにフォールバック任せにしない

`compactDialogText`が付与する省略記号`…`のように、**表示に使うすべての文字は`dialogMeasuredGlyphMetrics`に実測値を登録する**。登録し忘れると`uniformUnifontAdvance`のフォールバック（半角一律5px/全角一律9px）に落ちるが、これは実際の値と1px単位でズレることがある（`…`は実測4px）。1文字のズレでも、その文字が使われた行だけ他の行と揃わなくなる。新しい記号・絵文字的な文字を固定幅レイアウトに使うときは、まず実測してから使う。

## 各形の実装ノート

### 1. 比較表

- 2値は `ordered()` で大きい方を先に並べる（**勝者の位置を固定しない**。項目によって勝つ側が入れ替わる）
- 正規化%と実値を併記する（cpu-monkey方式）。%だけだと規模が消え、実値だけだと優劣が読めない
- 母数を必ず添える（例:「562人中417人」）
- 参考実装: `dialogComparisonTableSection`（`SLData.kt`）

### 2. 縦棒グラフ

- 濃淡・状態フラグ（進行中など）は色で。文字は `blocks` 配列（`▁▂▃▄▅▆▇█`）固定
- 目盛りは4本程度（Apple HIG）、`niceMax`で直感的な数列（1, 1.5, 2, 2.5, 3, 5, 7.5, 10 ×10ⁿ）に丸める
- セルhoverは `appendColoredCharsWithHover` でバケットのlabel+countを表示
- 参考実装: `buildDialogGraph`、使用例: `いいねが付くまでの日数`、`初速`、`月別ペース変化`、`週次いいね`、`リピーター率`

### 3. ヒートマップグリッド

- セル文字: `⬛`(U+2B1B)固定。実測送り幅8px（`dialogMeasuredGlyphMetrics`に記録済み）
- ラベル列幅:
  全角文字1つ分（9px）。空白行は半角スペース(4px)+NBSP(5px)の組み合わせで同じ9pxを作る（`dialogHeatmapAdvancePad`）
- 軸ラベルは間引く（Apple/GitHub式）。全部は出さない — 例: 時間軸は0,6,12,18,+右端に24、曜日軸は月水金日
- 色は5段階（`activityHeatmapColorStops`）、`scaleLevel`で平方根スケーリング（小さい値の差も見えやすくする）
- hoverの1行目は「{曜日}曜/{時}時」形式、灰色固定。2行目に件数（黄色）
- 参考実装: `dialogActivityHeatmapComponent`／`dialogActivityHeatmapSection`

### 4. ランキング一覧

- `dialogFixedLabel` で列幅を固定（値が変わっても位置がずれない）
- プレイヤー名: 大文字化 → `I`を`1`に置換 →
  10文字固定（`dialogRankingDisplayName`）。uniformフォントは小文字だと送り幅がばらつくため
- 建築名: 半角英数字を全角に変換 →
  10文字固定（`dialogBuildTitleDisplayName`、2026-08-17変更）。大文字化・記号除去はしない —
  建築名は大文字小文字・記号が意味を持つ
- 参考実装: `dialogStatsRankingSection`

### 5. 単純テキスト

- 比較や分布の形が要らない、1〜数行で完結する事実（例: 継続日数のサマリー行）
- 無理に棒グラフやヒートマップにしない（Apple HIG: 補助的な形をアプリの中心に据えない）

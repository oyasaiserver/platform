# `/sldata` ダイアログ 表記規約

Paper Dialog API でグラフを描くときの、文字・フォント・配色の決まり。 **実装前に必ず読むこと。** ここに書かれた規約を破ると列が崩れる。

**どのデータにどの「形」（比較表・棒グラフ・ヒートマップ・ランキング・単純テキスト）を選ぶかは
[GRAPH_SHAPES.md](GRAPH_SHAPES.md) を参照。** こちらは文字・フォント・配色の細則。

裏付けは Cogito Vault:

- `Knowledge/minecraft-username-font-width-normalization.md` — 文字幅の実測データ
- `Knowledge/minecraft-unihex-advance-width-formula.md` —
  送り幅の算出式（実機jarから逆算、2026-08-16）
- `Knowledge/minecraft-dialog-chart-lessons.md` — 過去に踏んだ失敗
- `Knowledge/apple-chart-design-framework.md` — グラフ設計の判断基準
- `Decisions/2026-08-15-sldata-chart-design.md` — 表示の型とカテゴリ分け

## `▁`は色を変えても実機では透明に見えない（2026-08-17発見）

`▁`(U+2581)を`hiddenColor`(黒)で塗って「見えない余白」として使う実装が複数箇所にあったが、
実機では影の描画などによりうっすら線が見えてしまう(ユーザーがスクリーンショットで発見)。

**本当に見えない余白が要る場所（右軸の余白、X軸ラベル行の空白区間など）はNBSP(` `)を使う。**
NBSPは中身が空のグリフなので、色に関係なく何も描画されない。`▁`は「見た目に線を出したい場所」 （棒グラフの地、ベースライン）専用に予約する。

## Kotlinソースにフィル文字リテラルを書くときは`\uXXXX`エスケープを使う（2026-08-17発見）

NBSP(` `)や全角スペース(`　`)などの空白系文字を`'　'`のように**直接貼り付けて**
コード編集すると、ツールのテキスト処理パイプラインで別の文字（多くの場合は半角スペース）に
正規化されてしまうことがあった。実際にこの事故で`padStart`のパディングが消える不具合が発生した。

**対策**: 空白系の文字リテラルは必ず`' '`や`'　'`のようにコードポイントのエスケープ表記で書く。
貼り付けた見た目が正しくても、実際に書き込まれたバイトを`python3 -c "print([hex(ord(c)) for c in open(...).read() if ...])"`
等で確認するまで信用しない。

## `stats2Text`はmdファイルの値がKotlinのデフォルト値より常に優先される（2026-08-17発見）

`sldata-stats2-text.md`にキーが存在する限り、Kotlin側のfallback文字列やプレースホルダの
デフォルト値を変えても**画面には反映されない**。プレースホルダのキー名を変えた場合は
「未知のプレースホルダ」警告を出してfallbackへ自動的に逃げるが、**キー名を変えずに文言だけ 変えた場合は無警告のまま古いmdの文言が使われ続ける**。

**コード側でtitle/desc/labelのデフォルト文言を変えたら、必ず`sldata-stats2-text.md`
（ソースツリー側とデプロイ先の両方）も同じ内容に更新し、`/sldata dialog reload`で 反映を確認すること。**

## 棒グラフの「最後の目盛り行」は実データの最下段そのもの（2026-08-17教訓）

一度「最後の目盛り行(例:160)とベースライン(0)の間に空白行が無い」ことを不具合と誤認し、
空白行を1行差し込む修正をしたが、これは誤りだった。**最後の目盛り行は、値が0より大きい
系列なら必ずバーが到達する最下段そのもの**であり、その直後に空白行を挟むと背の高い棒の
途中に穴が空いて見える(実機で発覚、修正を撤回)。ベースライン(0)は純粋に軸ラベル用の行で、 データの一部ではない。

## 鉄則

### 1行の中でフォントを混ぜない

行全体に一度だけ掛ける。segment ごとに付けない。

```kotlin
Component.text()
    .style(Style.style().font(DIALOG_FONT).build())   // ここで一度だけ
    .append(...)
```

**実際に起きた事故**: 名前ブロックだけ `.font(DIALOG_FONT)` を付け、バーと数値は未指定だった。 未指定は default
フォントになるため、同じ `█` でも送り幅が変わり、24個並べたバーが折り返した。

### 1行の中で送り幅を混ぜない

半角スペース（4px）とブロック文字（5px）を同じ行に置くと必ずずれる。 **空白が要る場所には半角スペースを使わない。**

## 使う文字

| 用途 | 文字 | 備考 | |---|---|---| | 棒の実績ぶん | `█` U+2588 | | | 棒の残りぶん | `█` U+2588 |
**色/濃淡で区別する。文字は変えない** | | 縦棒の端数 | `▂▃▄▅▆▇` | 1行未満の高さを表す | | 軸・地・空白の穴埋め | `▁`
U+2581 | **`_`（U+005F）は使わない** | | 名前列のパディング | `▁` U+2581 | 灰色にして目立たせない | |
ヒートマップのセル | `⬛` U+2B1B | **濃淡は色のみ。文字は固定**（2026-08-17変更、下記参照） |

### `░`(U+2591) と `▒`(U+2592)/`▓`(U+2593) は送り幅が違う（解決済み、2026-08-17）

2026-08-15に発見した送り幅不一致（`▒`/`▓` : `░` = 5 : 4）は、**濃淡の表現自体を文字差し替えから色分けに変更して解決した。**
活動リズムのヒートマップ（`dialogActivityHeatmapComponent`）は `⬛`
固定+5段階の色（`activityHeatmapColorStops`）に、
月別ペース変化の「集計途中の当月」表示（`buildDialogGraph`内）も `░` 文字置換から色分け（`incompleteColor`）に変更済み。
文字を統一した結果、この種の送り幅不一致は原理的に発生しなくなった。詳細は [GRAPH_SHAPES.md](GRAPH_SHAPES.md)
の「濃淡は色で表す」と Vault `Knowledge/minecraft-unihex-advance-width-formula.md`。

### `_` を使わない理由

`_`（U+005F）は `▁`（U+2581）とグリフ幅・送り幅が異なる。 混ぜると列がずれる。**アンダーバーが欲しい見た目でも `▁` を使う。**

### 横棒で「塗り＋アンダーバー」をしない

```
✗  ██████▁▁▁▁▁▁▁     実績と残りで文字を変える
✓  ████████████     文字は同じ。色と濃淡だけ変える
```

`▁` は縦位置が下寄りなので、`█` と並べると棒の続きに見えず別要素として読まれる。 **プレビューで確定した方式（`█` 一種類 +
色分け）を既定とする。**

縦棒グラフの「地」を `▁` で埋めるのは別の話。あちらは全面を `▁` で敷いて `█` を上書きする方式で、 `█` と `▁`
が同じ列に縦に並ぶことはないため問題ない。

## プレイヤー名

### 正規化

```
大文字化 → I を 1 に置換 → 10文字に整形
```

`marzipan99` → `MARZIPAN99` → `MARZ1PAN99`

uniform フォントは小文字だと送り幅がばらつく。大文字化すると揃い、 残る例外は `I`（他より狭い）だけなので `1` に置換して解消する。

### 列幅

```
10文字固定
  11文字以上 → 10文字で切る
  10文字未満 → 不足分を `▁` で埋め、その `▁` だけ灰色にする
```

### 統合版プレイヤーの先頭 `.`

**表示から完全に落とす。ツールチップにも出さない。**（2026-08-15 ユーザー判断）

`.` は Bedrock / Floodgate プレイヤーの識別子。本番のアクティブ比率は 23.7%。
送り幅が他と違い列を崩すため除去する。判別はツールチップのフル UUID で足りる。 統合版ゲーマータグに含まれうる半角スペースも同様に除去する。

## 数値

**全角を使う。** 桁数が違っても 9px 単位で揃うため、右端が一致する。

```
　１９８    ✓
 198       ✗ 桁数で右端がずれる
```

順位も同様に全角（`１位`）。

---

## 行の組み立て

各要素を固定幅にすることで、値が変わっても行の総幅が変わらないようにする。

```
[ヘッド 16x16] [１位　] [MARZ1PAN99　] [█×24 色分け] [　１９８]
```

| 要素 | 固定の仕方 | |---|---| | ヘッド | `width: 16` / `height: 16` /
`showDecorations(false)` | | 順位 | 全角固定 | | 名前 | 10文字固定 | | バー |
**常に24文字**。実績ぶんと残りぶんの合計が常に24 | | 数値 | 全角 |

**ラベル列は必ず固定幅にする。** `あなた`(3文字) と `全体平均`(4文字) をそのまま置くと バーの開始位置がずれる。短いほうを `▁`
で埋めて揃える。

## アイテム（プレイヤーヘッド等）

```kotlin
DialogBody.item(head)
    .description(DialogBody.plainMessage(component, bodyWidth))
    .showTooltip(true)
    .showDecorations(false)   // スロットの枠を消す
    .width(16).height(16)
```

**`width` / `height` はヘッドを拡大縮小しない。枠のサイズだけが変わる。** 大きくすると行間が広がるだけなので 16×16 に留める。

## 配色

### 名前付き16色

```
black  dark_blue  dark_green  dark_aqua  dark_red  dark_purple  gold  gray
dark_gray  blue  green  aqua  red  light_purple  yellow  white
```

### 任意 RGB

```yaml
color: "#7fbf3f"
```

**小文字のみ。** `#7FBF3F` のように大文字を書くと正規表現に一致せず、黙って既定色になる。

### 役割

| 役割 | 色 | |---|---| | 1位・強調 | gold | | 通常のデータ | green | | 残りぶん（未達） | dark_gray
| | ラベル・補助 | gray | | 注記 | gray（本文より小さく） |

**色だけで情報を運ばない。** Apple の指針。最新を示すなら色 + 位置、 最多セルを示すなら色 + 枠線のように、必ずもう一つ手掛かりを足す。

## 背景

**Dialog API に背景色の指定は無い。** `DialogBase` が持つのは
`title / externalTitle / canCloseWithEscape / pause / afterAction / body / inputs`
のみ。 マルチプレイでは `pause` も効かないため、背景は透過のまま。前景のコントラストで対処する。

## 検証

### ダンプだけで判断しない

`/sldata dialog stats2 dump` は**色を落とす**。実績ぶんの `█` と残りぶんの `█` が
同じ文字に見えるため、バーが伸縮しているかはダンプでは分からない。

**必ずスクリーンショットで確認する。**

```bash
python3 tools/shot.py "sldata dialog ranking" /tmp/out.png
```

### ビルド成功を「動く」と判断しない

コンパイルが通っても実行時に落ちることがある。 実例: FAWE の推移依存が Adventure 5.2.0 を持ち込み、Paper 実行時の 4.x と
`TextComponent.Builder.build()` の戻り値型が違って `NoSuchMethodError` になった。

**必ず実機でコマンドを実行し、画面が出ることを確認する。**

### 行が折り返していないか見る

`validateDialogLineAdvanceInvariant` は行同士の送り幅の一致を見るが、 **「そもそも本文幅に収まるか」は見ていない。**
目視で確認すること。

### 見た目の一次チェックは Gemini、裁定は必ず実測で

スクリーンショットの崩れ探しは Gemini に一次チェックさせてよいが、**指摘をそのまま実装依頼に回さない。**
実測（実際の画像を見る、必要ならピクセル計測やDB照合）で裁定してから Codex に渡す。
的中率は低い（実測で7〜8割は誤検出）が、見落としを拾うこともあるので一次スクリーニングとしては有効。 詳細は Vault
`Knowledge/sociallikes3-visual-review-pipeline.md`。

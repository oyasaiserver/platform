# OyasaiMusic

Minecraft 内でノートブロックの演奏を録音し、楽曲として公開・試聴・評価・プレイリスト化できる Paper プラグインです。楽曲は SQLite
と独自の音源ファイルとして保存され、通常の個人再生に加えて、アイテム化したレコードをジュークボックスへ設置する環境 BGM 再生にも対応します。

## 動作環境

| 項目 | 必要なもの | | --- | --- | | サーバー | Paper `1.21.11` | | Java | Java 21 | |
必須プラグイン | FastAsyncWorldEdit (FAWE) `2.15.2` 以降 | | 任意プラグイン | Vault
と経済プラグイン、TokenManager、PlaceholderAPI、Essentials、Floodgate |

FAWE は `/record we ...` でクリップボードを読むための必須依存です。Vault
が無い場合、金銭報酬の送金は行われません。TokenManager へのポイント付与は、設定したコンソールコマンドで行います。

## 導入

1. Paper と Java 21 を用意します。
1. FAWE と `OyasaiMusic-1.0.0.jar` を `plugins` フォルダへ配置します。
1. サーバーを起動します。
1. `plugins/OyasaiMusic/config.yml` を必要に応じて編集し、`/oyasaimusic reload` を実行します。

初回起動時に、データフォルダへ以下が作成されます。

```text
plugins/OyasaiMusic/
├─ config.yml             # プラグイン設定
├─ database.db            # 楽曲・ユーザー・プレイリスト等の SQLite データベース
├─ ranking_cache.json     # 日間・週間・総合ランキングのキャッシュ
├─ sound-catalog.json     # 看板用バニラ SoundEvent カタログ
├─ soundeffect/           # プラグイン通知用の録音済み効果音
│  ├─ publish_newsong.bin # 新曲公開時
│  └─ get_reward.bin      # 報酬受取時
└─ audio/
   └─ <作者名>/           # 楽曲の .bin 音源ファイル
```

統合版プレイヤー名に付く先頭の `.` は、`audio` 配下の作者ディレクトリ名から自動で除かれます。`database.db` と `audio`
は楽曲本体のため、サーバー移行・更新前には必ず両方をバックアップしてください。

## プレイヤー向けの使い方

### 楽曲を探して再生する

`/mm`
または音楽プレイヤーアイテムを右クリックしてメインメニューを開きます。公開済み楽曲の一覧、検索、日間・週間・総合ランキング、作者一覧、プレイリストを利用できます。楽曲名の近くには楽曲
ID が表示されるため、`/mm play <ID>` や `/mm open <ID>` でも直接アクセスできます。

楽曲詳細では試聴、前／次の楽曲への移動、いいね、お気に入り、プレイリストへの追加を行えます。非公開楽曲は、作者本人と管理者だけが確認でき、いいね・プレイリスト追加の対象にはなりません。

公開直後の新曲通知は `oyasaimusic.newsong.notify` 権限を持つプレイヤーだけに届きます。`[クリックで再生]`
をクリックするか、表示される `/mm open <ID>` を実行すると、詳細画面を開いて再生を開始します。

### 再生操作

GUI 下部の再生操作から、一時停止／再開、前後移動、シャッフル、ループを切り替えます。再生中の楽曲名と進捗はボスバーに表示されます。

- 曲の切替は 0.75 秒の間隔で行われます。
- プレイリストでは、1 曲ループ・リスト全体ループ・シャッフルの変更が次の遷移から即座に反映されます。
- 単曲の試聴でも、前後の公開曲へ移動できます。
- 一時停止／再開、操作不能などの短い通知はアクションバーに表示されます。重複いいね等の無効操作ではエラー音も鳴ります。
- 個人再生中は、再生している本人の頭上に1秒ごとに音符パーティクルが表示されます。環境BGMでは聴取者には表示せず、再生中のジュークボックス上にだけ表示されます。

### GUI のクリックモード

左側タブで操作モードを選択します。選択中のモードは黄緑で表示されます。

| 左クリック | 右クリック | | --- | --- | | Shift 左クリック | Shift 右クリック |

楽曲一覧の各アイテムの lore
には、各モードで実行される内容が表示されます。実行可能な操作は金色、操作のない項目は灰色です。統合版プレイヤー向けには、操作しやすいモード選択 UI
も提供されます。

## 楽曲を制作・公開する

### 基本の流れ

1. 下記いずれかの方法で録音します。
1. 録音完了後に自動で開く「楽曲設定」画面で題名、BPM、レコード種類、価格、参考 URL
   などを設定します。保存完了後は、開いているGUIと再生中のボスバーへ直ちに反映されます。
1. 必要であればオリジナル審査へ提出します。
1. 公開を ON にします。最初の公開時だけ通知権限所持者へ新曲通知が送られます。

録音された楽曲は初期状態では非公開の下書きです。公開状態と審査状態は別々に管理されます。オリジナル審査を提出した時点では「仮OK」となり、OPは審査画面で「許可」「未審査」「却下」へ切り替えます。楽曲設定で
BPM を変更すると、表示値だけでなく保存済み音源の時間間隔も変更され、実際の再生速度に反映されます。

### 収益化の条件

楽曲設定で **参考 URL を登録する**、または公開後に **オリジナル審査を申請する**
と、収益化対象になります。収益化対象の楽曲では、規定を満たした視聴による作者ポイントと、レコード購入額の作者還元を受け取れます。オリジナル審査は申請時点で仮OKとなるため、その時点から収益化対象です。

### 録音方式

| 方式 | 実行方法 | 用途 | | --- | --- | --- | | グリッド型 | `/record we grid <BPM>` |
等間隔に並べたノートブロックを、向きと BPM から順に読み取る | | 回路型 | `/record we default` |
ダスト・土台・リピーターの伝搬を仮想シミュレーションして記録する | | 生演奏録音 | `/record live` → 演奏 →
`/record stop` | 現在地から48ブロック以内で実際に鳴らしたノートブロックを実時間で記録する | | 現地回路録音 | `//copy` →
`/record we start <RStick>` → コピー元の電源を作動 → `/record stop` |
コピー元の範囲だけで発生した本家の回路演奏を記録する。`0.5/1/2/3/4`
RStick（50/100/200/300/400ms）単位で時刻を丸め、サーバーラグの揺れを抑える。 |

FAWE 録音では、先に対象範囲を `//copy`
してください。グリッド型・回路型は、コピー元の構造（看板を含む）をワールド上に残したまま録音することを推奨します。回路型では信号源からノートブロックへの経路、リピーターの向き、遅延を考慮して解析します。

生演奏録音は量子化を行わず、`NotePlayEvent`
の実際の発音間隔をそのまま保存します。現在地から48ブロック以内だけを記録するため、長い演奏に沿って移動しても録音範囲は追従します。現地回路録音はクリップボードの座標範囲だけを対象にし、新しいワールドや一時ブロックを作成しません。どちらも音量100・Pan
0で、録音開始前の無音は保存時に除去されます。

### ノートブロック制作を補助するおすすめ導入（任意）

ノートブロック回路を組んで録音する場合は、次の導入をおすすめします。OyasaiMusic
の利用に必須ではありませんが、音階・音色を目で確認しながら設定しやすくなります。導入できる Minecraft
バージョン・ローダーは各配布ページで確認してください。

- [Note Block Tweaks](https://modrinth.com/resourcepack/note-block-tweaks)（リソースパック）:
  ノートブロック音楽制作用の表示補助リソースパックです。
- [Note Block Tuner](https://modrinth.com/mod/note-block-tuner)（Fabric・クライアントMod）:
  現在の音階・音色を表示するGUIから、音階を選んで自動調律できます。マルチプレイでもクライアント側だけで動作します。

### ノートブロック上の看板による上書き

ノートブロックの真上（Y+1）に看板を置くと、録音時にそのノートの設定を上書きできます。

| 看板の行 | 記述 | 例 | 効果 | | --- |----------------------------| --- | --- | | 1 行目 |
音量 `0`〜`100`（`%` 可） | `80` / `80%` | ノートの音量を上書き | | 2 行目 | Pan `-100`〜`100` (-:左
+:右) | `-50` | 立体音響再生時の左右定位を上書き | | 3 行目 | 四分音符を基準とする遅延 | `1/8` / `-1/16` |
正値は遅らせ、負値は早める | | 4 行目 | バニラ SoundEvent の指定 ID | `4.5.1:2` |
ノートブロック音色を指定音源・パターンに置換 |

3 行目の `1` は四分音符 1 個分、`1/2` は八分音符 1 個分です。遅延の基準 BPM はグリッド型なら指定
BPM、回路型・生演奏・現地回路録音は基準 120 BPM です。

4 行目の ID は `sound-catalog.json` によって決まります。たとえば `entity.axolotl.attack` のパターン 1 は
`4.5.1:1`、`ui.loom.select_pattern` のパターン 4 は `8.3.1:4` のように指定します。音量は看板 1
行目（未指定時は元ノート）、ピッチは看板下のノートブロックを使います。

楽曲設定画面でも左の「アクションモード切替」を使えます。レコード種類は左クリックで次、右クリックで前の種類へ切り替えます。統合版でも左クリック／Shift左クリック／右クリック／Shift右クリックの4モードを選択できます。

設定画面の「FAWEクリップボードを再読み込み」は、クリック方法で録音方式を選びます。

| 操作 | 方式 | 動作 | | --- | --- | --- | | 左クリック | `/record we grid <BPM>` |
現在の楽曲BPMで、クリップボードを即時にグリッド型として上書き | | Shift左クリック | `/record live` |
生演奏録音を開始。`/record stop` で現在の楽曲へ上書き | | 右クリック | `/record we start` |
現地回路録音を開始。`/record stop` で現在の楽曲へ上書き | | Shift右クリック | `/record we default` |
クリップボードを即時に回路型として上書き |

設定画面から始めた現地回路録音は、直前に指定したRStickを引き継ぎます。未指定時は1RStick（100ms）です。回路を起動する前なら
`/record we start <RStick>` で変更できます。

## SoundEvent カタログ

`sound-catalog.json` は JAR
内の初期カタログを初回起動時にデータフォルダへ展開したものです。カタログの読み込みに失敗した場合、`/demosound` の TAB 補完や 4
行目指定は利用できません。

- 基本的にはファイルを手編集せず、そのまま使用してください。
- 変更した場合は `/oyasaimusic reload` で再読み込みします。
- 音源ごとに存在するパターンだけを `/demosound` の補完候補に出します。
- `Sound.values()` 等の Bukkit の列挙 API には依存せず、カタログ定義から解決します。

## レコードアイテムと環境 BGM

楽曲をアイテム化したレコードは、ジュークボックスへ右クリックで設置できます。独自音源のためバニラのジュークボックス内部には保存せず、設置位置をプラグインが管理します。設置時にはレコードを消費するため、クリエイティブモードでの複製も発生しません。

レコードを Shift + 右クリックすると環境 BGM
設定を開けます。再生範囲、トリガー、ループを調整できます。新規レコードの再生範囲は半径16ブロックです。

再生範囲は権限ごとに個別に許可されます。設定画面では自分に許可された範囲だけを選択でき、権限のない範囲が保存されたレコードもジュークボックスへの設置時に拒否されます。

| 再生範囲 | 必要権限 | | --- | --- | | 半径16ブロック | `oyasaimusic.record.range.16` | |
半径64ブロック | `oyasaimusic.record.range.64` | | 半径256ブロック |
`oyasaimusic.record.range.256` | | ワールド全体 | `oyasaimusic.record.range.world` |

| トリガー | 動作 | | --- | --- | | ジュークボックス | 設置と同時に再生 | | RS 信号 | ボタン等の ON
になった瞬間で再生／停止を切替。ON を保持しても再生は継続 | | 接近 | 指定範囲にプレイヤーが入ると再生し、全員が離れると停止 |

手ぶらでジュークボックスを右クリックすると環境 BGM を停止してレコードを取り出せます。ジュークボックスを壊した場合も、登録済みの再生は解除されます。

## 報酬・統計・ランキング

### 作者が収益を得る条件

参考 URL を登録した楽曲、または公開後にオリジナル審査を申請して仮OK以上になった楽曲は、**収益化対象**です。参考 URL
の登録・オリジナル審査の申請のどちらか一方で条件を満たします。

| 種類 | 発生条件 | 初期設定の報酬 | | --- | --- | --- | | いいね報酬 | 公開楽曲へ未いいねのプレイヤーがいいねする |
作者: `2pt`、送信者: `1000円` | | 視聴報酬 | 収益化対象の楽曲で有効な視聴が合計10回に到達するごと | 作者: `1pt` | |
レコード売上 | 収益化対象の楽曲のレコードを購入する | 作者: 購入額の `80%` |

いいねは公開楽曲だけに付けられ、同じプレイヤーによる重複いいねはできません。いいねによる作者ポイントは収益化の条件を満たしていない楽曲にも付与されます。作者がオンラインなら、いいねを受けた際に楽曲名・送信者名を含むトースト通知も表示されます。

有効な視聴として数えるには、次をすべて満たす必要があります。

- 楽曲の総演奏時間の80%以上を聴き終える（`playback.view-completion-ratio`）
- AFKではない。PlaceholderAPI と Essentials がある場合は `%essentials_afk%` で判定
- 同じプレイヤーによる同じ楽曲の視聴が、1時間3回・1日10回以内
- ジュークボックスの環境BGMではなく、個人再生である

報酬は即時に失われず未受取残高へ蓄積され、トップメニューの「未受け取り報酬を受け取る」から受け取れます。金銭はVault経済へ、ポイントは
`economy.points-command`（既定値:
`tokenmanager add %player% %points%`）で付与します。報酬額・回数制限・視聴完了率は `config.yml`
から変更できます。

作者の未受取報酬は報酬受取バンドルに、今回の受取額・ポイント・総収入とともに表示されます。ランキングは日間・週間・総合の楽曲／作者を表示し、管理者は
`/oyasaimusic update` で即時更新できます。

## 設定

主な設定は `plugins/OyasaiMusic/config.yml` にあります。

| 設定 | 説明 | | --- | --- | | `storage.database-file` | SQLite データベースのファイル名 | |
`storage.audio-directory` | 音源ファイルの保存先 | | `recording.default-price` | 新規楽曲の既定価格
| | `recording.default-record-material` | 新規楽曲の既定レコード素材 | |
`playback.default-mode` | `default` または `positional`。既定の再生方式 | |
`playback.view-*` | 視聴数に数える回数上限・完了率・ポイント換算 | | `economy.like-reward-*` |
いいね時の通貨／ポイント報酬 | | `economy.record-sale-author-share` | レコード売上の作者還元率 | |
`economy.points-command` | ポイントを付与するコンソールコマンド | | `bedrock.name-prefix` |
統合版プレイヤー名を判定する接頭辞 |

TokenManager を使う場合の既定値は以下です。

```yaml
economy:
  points-command: "tokenmanager add %player% %points%"
```

`%player%` は受取プレイヤー名、`%points%` と `%amount%` はポイント値に展開されます。設定を変えた後は
`/oyasaimusic reload` を実行してください。

## プラグイン効果音

新曲公開時と報酬受取時には、録音済みの `.bin` 効果音を再生します。初回起動で `soundeffect`
フォルダへ標準音源が展開されます。将来の拡張用に、効果音はこのフォルダから読み込む構造です。同じファイル名の有効な OYMB 形式 `.bin`
に差し替えると、次回の該当通知から任意の効果音を利用できます。

## プレイヤーヘッド

オフラインプレイヤーのヘッドは、Paperのローカルキャッシュにスキンがあればそれを使用します。未キャッシュのJava版プレイヤーだけはPlayerDBのUUID
APIで補完し、統合版（設定した名前接頭辞）はスティーブ頭のまま表示します。MojangのプロフィールAPIは使用しません。取得結果・取得失敗はキャッシュされ、同じUUIDへの同時問い合わせは1回にまとめられます。

## 運用上の注意

- 公開楽曲だけが一般の一覧・検索・ランキング・いいね・プレイリスト追加の対象です。
- 楽曲を削除すると、そのIDは次回以降の録音完了時に最も小さい欠番から再利用されます。
- `/oyasaimusic reload`
  は設定・カタログ等を読み直しますが、進行中の録音や再生を再構築するためのコマンドではありません。設定変更は人の少ない時間帯に行うことを推奨します。
- データベースファイルだけを移動して `audio` を移動しないと、楽曲情報は残っていても再生できません。
- `sound-catalog.json` が削除・破損した場合は、バックアップから戻すか、プラグイン JAR 内の同名ファイルをデータフォルダへ復元してから
  `/oyasaimusic reload` を実行してください。

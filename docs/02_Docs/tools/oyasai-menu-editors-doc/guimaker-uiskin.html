UIスキンの概念

GuiMakerが提供する各エディタ画面のスロット配置・アイコンを上書きするための機能です。 つまり「GuiMakerのGUI自体」をプレイヤー（OP）がGUI上でカスタマイズできるようにする層です。

定義ファイル: gui-maker-ui-screens.yml

  • 初回起動時にプラグインリソースから自動コピー
  • 各画面 (hub, context, action_type, ...) ごとに既定のスロット定義を保持
  • plugin側で GuiMakerUiSkinDefinitions.load でロード
  • 欠けているキーは mergeBundledDefaults でバンドル版から自動補完

カスタマイズデータ: ui-skin/<screen>.yml

個別画面ごとのプレイヤーカスタマイズ。positions (機能の配置スロット), icons (装飾アイコン), enabled (有効ラベル一覧) を保存。

主要クラス

  • GuiMakerUiSkinDefinitions (object) — バンドル/カスタマイズ済み定義のロード
  • GuiMakerUiSkinStore — ui-skin/<screen>.yml のCRUDとキャッシュ
  • UiSkinData(positions, icons, enabledLabels) — メモリ表現
  • UiScreenCatalog(restoreSlots, screenDefs, defaultGlassByScreen, fallbackGlass) — 全体定義

復元スロット (UI_SKIN_RESTORE_SLOTS)

デフォルトでは [47, 48, 50, 51]。非表示にした機能ラベルを再追加するための「追加候補」枠です。

復元スロット (47/48/50/51) をクリックそこに表示中の非表示ラベルを再追加

slot 52openUiSkinBlockPicker へ
slot 53キャンセル (closeInventory)

シャドウルール (プレイヤーインベ干渉防止)

プレイヤーインベントリでの shift-click や HOTBAR_SWAP, COLLECT_TO_CURSOR などはスキンアイテムが混入しないようevent.isCancelled = true。

OnInventoryClose時の処理

カーソル上にスキンアイテム (KEY_SKIN_ITEM PDC付き) が残っていた場合、1tick遅延で setItemOnCursor(AIR) して破棄する。

UIブロックピッカー (openUiSkinBlockPicker)

編集中の画面（または全画面）で利用可能な機能ブロックをインベントリへ取り出せるピッカー。

レイアウト

  • グリッド 0-44 に最大45件のUIブロック
  • slot 45: 状態表示 (この画面のUIブロック / 全UIブロック / ページ表示)
  • slot 48: 前のページ
  • slot 49: 表示切替 (allScreens トグル)
  • slot 50: 次のページ
  • slot 53: UI編集に戻る

アイテム表示

状態表示
同じ画面の機能 (compatible=true)&b<label> / 「クリックでインベントリに追加」
別画面の機能 (compatible=false)&7<label> / 「別画面用: この画面には配置できません」

クリック動作

  • 機能ブロックを左クリック → 同じ画面用なら player.inventory.addItem で配布
  • 別画面のブロックは「&cこのUIブロックは別画面用です」と通知して何もしない

YAMLファイル構造

gui-maker-ui-screens.yml (定義側)

restore-slots: [47, 48, 50, 51]
fallback-glass: GRAY_STAINED_GLASS_PANE
screens:
  hub:
    default-glass: GRAY_STAINED_GLASS_PANE
    slots:
      10:
        label: "通常GUI"
        material: ENDER_CHEST
      12:
        label: "Popupメニュー"
        material: CHORUS_FRUIT
      # ...
  context:
    default-glass: BLUE_STAINED_GLASS_PANE
    slots:
      10:
        label: "名前を設定"
        material: NAME_TAG
      # ...

ui-skin/<screen>.yml (カスタマイズ側)

schema: 3
positions:
  0:
    label: "名前を設定"
    slot: 19
  1:
    label: "ロアを追加"
    slot: 28
icons:
  10: NETHERITE_INGOT
  11: DIAMOND
enabled:
  - "名前を設定"
  - "ロアを追加"
  - "権限を設定"

スキーマと後方互換

UI_SKIN_SCHEMA_VERSION = 3。schema未満のファイルを読み込んだ場合、レガシー対応として「slot 0 またはアイテムプレビューラベルを自動的にenabledに追加」(legacyEnabledAdditions) します。

positions のロード仕様 (後方互換)

3形式に対応:

  1. 新形式: positions.<n>: {label: ..., slot: ...}
  2. 中間形式: positions.<label>: <slot> (キーに直接ラベル)
  3. レガシー形式: positions.<label>.<sublabel>: <slot> (ネスト1段)

enabled / hidden の二択

  • enabled: [...] が存在: 明示的に有効化されたラベル一覧として読み込み
  • hidden: [...] が存在: 「全ラベル - hidden」を有効化
  • どちらも無い場合: enabledLabels = null (= 全部有効)

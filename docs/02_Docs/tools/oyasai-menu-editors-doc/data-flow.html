ドラフト / ライブ分離

GuiMakerは編集中の状態をドラフトとして保存し、明示的にcommitするまでライブに反映しません。

分離の意義

  • 編集中の未完成版を放置してもサーバーに影響しない
  • commitした瞬間に plugin.reload() が走り全プレイヤーに反映
  • revertでドラフトを破棄してライブに戻せる

パス対応

種類ドラフトライブ
通常GUIguimaker/<id>.ymlmenus/<id>.yml
Popupguimaker/popup/<id>.ymlmenus/popup/<id>.yml

主要関数 (GuiMakerExporter)

関数動作
exportDraftセッションをドラフトに書き出す
hasDraftドラフトが存在するかチェック

revertDraftドラフトファイルを削除

編集データフロー

セッションの読み込み

1. /guimaker edit <id> または UI から ID をクリック
2. resolveSession 既存セッションがあれば返す。なければ新規 GuiEditorSession
3. loadIntoSession draft → live の順でファイル検索 → parseYamlIntoSession
4. PDC埋め込み 各スロットに ItemStack を作り、PDC に name/lore/perm/actions/extras を設定
5. openCanvas canvasInventoryを作成、PDC付きアイテムを配置

編集中の自動保存

キャンバスでアイテム移動 onInventoryClick → 1tick後にrebuildSlotsFromInventory
各種編集操作 applyPdcToItem(session, slot) でPDC更新 + saveWorkingCopy
saveWorkingCopy テンプレート編集中 → テンプレートファイル / 通常 → exportDraft
onInventoryClose キャンバスを閉じたタイミングで saveWorkingCopy が呼ばれる

commitフロー

1. エディタバー slot 48 (または /guimaker edit <id> commit)
2. テンプレート編集中? はい → テンプレートファイル保存で終了
3. rebuildSlotsFromInventory PDCから session.slots を再構築
4. GuiMakerExporter.commit writeYaml/writePopupYaml でライブファイルへ
5. plugin.reload() 全YAMLのリロード、開いているメニューも更新

テンプレート編集の保存先切替

session.templateEditTarget != null の場合、commitせずとも編集ごとに GuiTemplateStore.saveEditedTemplate でテンプレートファイルへ直接保存される。 エディタバーの slot 48 が「テンプレート保存」ラベルに変化し、押すと saveTemplateEdit が呼ばれる。

通常GUIのYAML (writeYaml)

構造

menu:
  title: "&8メニュータイトル"
  size: 54
items:
  item_0:
    slot: 0
    icon: ENDER_CHEST
    name: "&aクリック！"
    lore:
      - "&7説明1"
      - "&7説明2"
    permission: "lpgroup:builder"
    enchanted: true
    actions:
      - type: OPEN_MENU
        target: shop_main
      - type: SOUND
        sound: ui.button.click
        volume: "1.0"
  item_10:
    slot: 10
    icon: DIAMOND
    actions:
      - type: PLAYER_CMD
        command: "spawn"

パース順序 (parseYamlIntoSession)

  1. menu.title / menu.size を読む (size は ((n+8)/9)*9 で9の倍数化)
  2. items の各セクションを走査
  3. slot, icon, name, lore, permission, enchanted, actions を取得
  4. 各 GuiSlotDef を session.slots に登録
  5. ItemStack + ItemMeta を作って PDC をすべてセット
  6. tempInventory に配置 → session.canvasInventory にセット

書き込み順序 (writeYaml)

  1. menu.title / menu.size を書く
  2. canvasInventory を走査 (slot 0 から size-1)
  3. 各アイテムについて key = "items.item_$slot" で書き出し
  4. name は def.name > meta.displayName の順で取得
  5. lore は def.lore > meta.lore の順で取得
  6. actions は List<Map<String, Any>> として書き出し

PopupのYAML (writePopupYaml)

構造

title: "&8Popupタイトル"
glass: GRAY_STAINED_GLASS_PANE
nav_active: -1
items:
  shop_button:           # キー(item_N または extras.popup.key)
    slot: 10
    icon: CHEST          # or CUSTOM_HEAD (PLAYER_HEAD + texture)
    texture: "https://..."
    name: "&aショップ"
    lore:
      - "&7商品を売買"
    enchanted: false
    required_permission: "lpgroup:default"
    op_only: false
    fallback_icon: AIR
    fallback_texture: "https://..."
    fallback_name: "&8未開放"
    fallback_lore:
      - "&7条件を満たすと表示されます"
    actions:
      - open_menu: "shop"
      - close: true
    fallback_actions:
      - chat_paste: "..."

通常GUIとの大きな違い

  1. itemsキー名がカスタマイズ可能: extras["popup.key"] があればそれ、なければ item_$slot
  2. slot制限: 0..44 のみ（45-53はナビバー予約）
  3. permissionキー: required_permission (通常GUIは permission)
  4. actions形式: 通常GUIは type: TYPE + キー、Popupは player_cmd: / open_popup: 等のショートキー
  5. fallback_*: 権限なしプレイヤー向けに別アイコン・テキスト・アクションを設定可
  6. CUSTOM_HEAD: PLAYER_HEAD + texture URL でスキンヘッドを表示
  7. op_only: trueならOPのみに表示

キー名の重複対策 (uniquePopupKey)

同じpopup.key を持つアイテムが複数ある場合、<key>_2, <key>_3 ... と連番をつけて重複回避。

アクションマッピング (popupActionMap)

GuiActionDef → PopupActionType → YAMLキー名 の変換。PopupActionType に存在しない値 (SOUND, BROADCAST, MESSAGE, PARAM_COMMAND, OPEN_MACRO以外の一部) はnullを返し、YAML出力時にスキップされる。

アクション逆変換 (parsePopupActions)

YAMLマップのキー (player_cmd, open_popup, ...) から GuiActionDef に変換:

map.containsKey("player_cmd") -> GuiActionDef("PLAYER_CMD", mapOf("command" to ...))
map.containsKey("open_popup") -> GuiActionDef("OPEN_POPUP", mapOf("target" to ...))
map.containsKey("open_sell") -> GuiActionDef("OPEN_SELL")
// etc.

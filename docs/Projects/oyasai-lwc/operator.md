# OyasaiLWC の運用（運営向け）

プレイヤー向けの操作は [player.md](player.md)、内部の仕組みは [PROJECT.md](PROJECT.md) を参照。

## 権限

| 権限 | 既定 | できること |
|---|---|---|
| `lwc.protect` | 全員 | `/lock` などのコマンドを使う。**管理者もこれが必要** |
| `lwc.admin` | OP | 他人の鍵付きブロックを使う・壊す、コマンドで鍵を外す・共有を変える |

- OP は `lwc.admin` がなくても管理者として扱われます。
- 保護操作のコマンドはプレイヤー専用です。コンソールからは使えません（廃止コマンドだけは誰が打っても「廃止しました」を返す）。
- `lwc.protect` はコマンドを打った時点でだけ確認します。権限を外しても、待機中の操作や実行中の自動保護モード（最大60秒、容器設置で延長）は止まりません。
- 管理者も、展示用の鍵（display）の出し入れ制限は受けます。

## 他人の鍵を扱う

運営専用のコマンドはありません。`lwc.admin` を持った状態で、プレイヤーと同じコマンドを使います。

| 対応 | 方法 |
|---|---|
| 持ち主を調べる | `/cinfo` → 右クリック |
| 放置された鍵を外す | `/unlock` → 右クリック。またはブロックを壊す（ラージチェストは鍵の記録側を壊したときだけ外れる） |
| 共有を代わりに設定する | `/cmodify 名前` → 右クリック |
| 展示の中身を入れ替える | `/unlock` → 入れ替え → `/cdisplay` でかけ直す（元の持ち主ではなく、作業した人の鍵になる） |

持ち主の変更、一括削除（旧 `/cremoveall`）、プレイヤーごとの上限（旧 `/climits`）の機能はありません。

## 守られるもの・守られないもの

- **守られる:** 他人による開閉・破壊、爆発、ピストンでの押し引き、延焼、鍵付き容器とのホッパー移動（`/chopper on` で許可。移動元・移動先のどちらかが off なら止まる）
- **守られない:**
  - 支えのブロックを壊したときの巻き添え。爆発や破壊で除外するのは保護ブロック自体だけで、看板・ドアなどを支える未保護ブロックは守らない（落ちたあとの挙動はゲーム内で未確認）
  - 鍵をかけていないブロック。置いただけでは保護されない
  - レッドストーンでのドア開閉、ディスペンサーの発射などのブロック自体の動作
  - 他のプラグインがすでにキャンセルした操作。そのイベントは処理しない
- 保護はワールド**名**と座標で記録されます。ワールド名を変えると、そのワールドの保護は効かなくなります。
- 記録されたブロックの種類（DB の blockId）とは照合しません。座標と、今そこにあるブロックが保護対象の種類かどうかで判定します。
- ブロックが置かれると、その座標に残っていた古い保護は消えます（自動保護モードの有無に関係なく）。ワールドの復元やブロックの置き換えをしたあとは、件数だけでなく実際のブロックで確認してください。

## データと設定

- **データ:** `plugins/OyasaiLWC/lwc.db`（SQLite）。外製 LWC と同じ形式（version 6）。設定ファイルはありません。
- **起動時のログ:** 読み込んだ保護の件数と、読み飛ばした未対応 type の件数が出ます。件数は DB の行数です。今そこに保護対象のブロックがあるかどうかは確認していません。
- **起動しないとき:** プラグインは無効化され、ログに理由が出ます。主な原因は次のとおり。
  - DB の version が 6 以外（この場合、DB には書き込まない）
  - 同じ座標の保護が重複している
  - owner の UUID や data の JSON が壊れている、`lwc_internal`・`lwc_protections` テーブルがない
  - `lwc_blocks` テーブルがないときは起動できるが、新しく鍵をかけるときに保存が失敗する
  - SQLite に接続できない
  - 旧フォルダからのコピーに失敗した（新フォルダは作られないので、原因を直せば次の起動でやり直せる）
- **保存の失敗:** 鍵の追加・削除は保存が終わるまで待ちます。共有（`/cmodify`）とホッパー（`/chopper`）の変更は、保存を待たずに成功メッセージを出します。保存に失敗すると、ログに `LWC データベースの書き込みに失敗しました` が出ます。この場合、プレイヤーには成功と表示され、ゲーム内でも設定が効いたままになりますが、再起動すると元の設定に戻ります。
- **停止時:** 保存待ちの書き込みが終わるまで待ってから DB を閉じます。

## 外製 LWC からの移行

1. 外製 LWC の jar を外す。
2. `plugins/OyasaiLWC/` が**存在しない**ことを確かめる。空のフォルダがあるだけでもコピーは行われず、空の新しい DB で起動して保護が0件になる。
3. OyasaiLWC を入れて起動する。`plugins/LWC/` の中身（`lwc.db`・SQLite の補助ファイル・設定・サブフォルダ）を丸ごとコピーする。旧フォルダは残る。
4. 起動ログの保護件数と、読み飛ばした件数を確認する。
5. 本番で動作を確認してから、旧フォルダを手動で消す。

**引き継がれるもの・引き継がれないもの:**

- 有効になるのは private（type 2）と display（type 6）の保護だけです。public・パスワード・寄付などの行は DB に残りますが、読み込まれず効きません。
- 共有はプレイヤー単位（UUID）のものだけが効きます。グループ単位の共有などは効きません。
- フラグは HOPPER だけが効きます。履歴、WorldGuard・経済連携、MySQL も引き継がれません。
- 効かない設定も、読み込んだだけでは DB から消しません。ただし `/cmodify` でそのプレイヤーの共有を変えると、同じプレイヤーに付いていた旧権限は新しい設定に置き換わります。
- 外製 LWC がラージチェストの両側に別々の保護を記録していた場合、統合しません。操作によって参照される側が変わり、`/unlock` しても片側の保護が残ることがあります。`/cinfo` で両側を確認してください。

## 他のプラグインとの連携

- `provides: [LWC]` を宣言し、SignShop が使う最小限の API（保護の有無、使える人かどうか）だけを持ちます。外製 LWC と完全な互換性があるわけではありません。
- SignShop などが使う「自動で鍵をかける API」（`protectBlock`）には対応していません。連携先にその機能があっても、鍵はかかりません。

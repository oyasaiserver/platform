# OyasaiBan の運用（運営向け）

Velocity（プロキシ）で動く BAN 管理です。BAN はプロキシへの接続時に判定するので、全サーバーに効きます。
プレイヤー向けの案内は [player.md](player.md)、内部の仕組みは [PROJECT.md](PROJECT.md) を参照。

## 権限

| 権限 | 既定 | できること |
|---|---|---|
| `oyasai.ban` | 誰も持たない（Velocity には OP がないため、LuckPerms などで付与する） | `/ban`・`/unban`・`/check`・`/history`・`/banlist` |

- プロキシのコンソールは権限なしで上の5つを使えます。コンソールからの BAN は執行者が `CONSOLE` と記録されます。
- `/oyasaiban`（`reload`・`import`）はコンソール専用です。プレイヤーには権限に関係なく使えません。
- 権限のないプレイヤーが `/ban` などを打った場合、プロキシのコマンドとしては扱われません。その先（バックエンドのサーバーにコマンドが渡るか）は未確認です。

## コマンド

| コマンド | 用途 |
|---|---|
| `/ban <名前> [期間] <理由...>` | BAN する。期間を省くと永久BAN。理由は必須 |
| `/unban <名前>` | 有効な BAN を解除する |
| `/check <名前>` | 有効な BAN の種別・理由・執行者・開始・期限を表示する |
| `/history <名前>` | BAN 履歴を新しい順に表示する（種別・開始日時・理由・執行者） |
| `/banlist [ページ]` | 有効な BAN を新しい順に、1ページ10件で表示する（名前・UUID・種別・期限） |
| `/oyasaiban reload` | `config.yml` を読み直す |
| `/oyasaiban import <dry-run\|run> <フォルダ>` | AdvancedBan のデータを確認・取り込みする（後述） |

### `/ban` の書き方

- 期間は `s`（秒）・`mi`（分）・`h`（時間）・`d`（日）・`w`（週）・`mo`（30日）・`y`（365日）。`1w2d` のようにつなげられます。大文字でも構いません。
- **`m` は使えません**（分は `mi`、月は `mo`）。`0s` のような長さ0も不可です。
- 2番目の語が期間として読めれば期間BAN、読めなければ**そこから先がすべて理由**の永久BANになります。ただし数字で始まる語は期間とみなし、形式が不正なら「期間の形式が不正です」で止まります。このため、永久BANの理由を数字で始めることはできません。
- 期間だけで理由がないと「理由を指定してください」、極端に長い期間は「期間が長すぎます」で止まります。
- **すでに有効な BAN がある相手には BAN できません**（「すでにBANされています」）。理由や期間を変えたいときは `/unban` してから BAN し直します。
- Tab 補完は `/ban` だけにあります（接続中の名前、期間の例、理由の例）。

### BAN したときに起きること

1. 相手が接続中なら、BAN 画面を表示して切断する
2. 接続中の全員に「[ＢＡＮ] 名前 がBANされました。」を出し、効果音を鳴らす
3. Webhook が設定されていれば Discord に通知する（後述）

表示・記録される名前は、`/ban` に**打ち込んだ文字列そのまま**です（大文字小文字も含む）。`uuid:` 形式で BAN すると、一覧・全体通知・Discord 通知の名前が `uuid:…` になります。

### 名前の指定と解決

`/ban`・`/unban`・`/check`・`/history` の名前は、次の順に UUID へ変換します。

1. `uuid:<UUID>` 形式ならその UUID（ハイフンありの形式）
2. 接続中のプレイヤー
3. このプラグインが記録した名前（ログインした人・BAN した人・取り込んだ人。大文字小文字は区別しない）。同じ名前が複数あれば最後に記録された方
4. `.` で始まる名前は Bedrock 名として Floodgate に照会（Floodgate がないときは解決できない）
5. それ以外は Mojang の公開 API に照会（英数字と `_` の16文字以内だけ）

解決できないと「UUIDを解決できませんでした」で止まります。手順3は過去の記録を優先するため、名前を変えた人・同じ名前を後から使い始めた人を取り違えることがあります。対象を確実に指定したいときは `/check` で UUID を確かめてから `uuid:` 形式を使ってください。

### 表示

- `/check`・`/history`・`/banlist` に UUID が出ます。プレイヤーはクリックでコピーできます。
- 時刻は日本時間（`yyyy-MM-dd HH:mm:ss JST`）です。
- コマンドが内部で失敗すると「○○に失敗しました。コンソールを確認してください。」と出ます。原因はプロキシのログにあります。

## 設定と Discord 通知

設定ファイルは `plugins/oyasaiban/config.yml`。無ければ起動時（と `reload` 時）に作られます。

```yaml
webhook-ban-url: ""
```

- `webhook-ban-url` に Discord Webhook の URL を入れると、BAN のたびに通知します。既定は空（通知しない）。**実際の URL は公開文書や公開リポジトリに書かないでください。**
- 変更は `/oyasaiban reload` で反映されます。結果は `OYASAIBAN_RELOAD ok webhook=set`（または `empty`）、失敗時は `OYASAIBAN_RELOAD_ERROR` です。URL そのものは表示しません。
- 読み込みは簡易的で、`#` 以降をコメントとして切り捨てます。`#` を含む URL は正しく読めません。
- 通知の内容は、対象の名前・執行者・期間（打ち込んだ文字列、省略時は「永久」）・**理由の最初の1語だけ**です。サムネイルとして外部サービス（vzge.me）から対象の名前で頭像を読み込みます。
- 未設定のままだと BAN のたびにログに `BAN webhook URL is not set.` が出ます。送信の失敗はログに出るだけで、BAN 自体は成立しています。

## データ

- `plugins/oyasaiban/punishments.db`（SQLite。WAL 方式なので `-wal`・`-shm` ファイルも付く）。コピーやバックアップはプロキシを止めてから行ってください。
- 有効な BAN、BAN の履歴、名前と UUID の記録（**ログインした全プレイヤー**の最後の名前と時刻）を持ちます。
- `/unban` は有効な BAN だけを消します。履歴は残りますが、**誰がいつ解除したかは記録されません**。
- 期限は終了時刻ちょうどに切れます。期限切れの BAN は、誰かのログイン・`/ban`・`/check`・`/banlist`・`import run` のときにまとめて有効データから消えます（履歴は残る）。
- ログイン時の確認に失敗すると、そのプレイヤーの接続を拒否します。**起動時に DB を開けなかった場合は、全員が接続できなくなります**（全員に「BAN情報の確認に失敗しました」）。プロキシのログで原因を確認してください。

## AdvancedBan からの取り込み

コンソールで実行します。`<フォルダ>` は AdvancedBan のデータフォルダ（`storage.script` がある場所）。相対パスは `plugins/oyasaiban/` 基準です。

1. `oyasaiban import dry-run <フォルダ>` で件数と未解決を確認する（DB は変えない）
2. 問題なければ `oyasaiban import run <フォルダ>` で取り込む

- `storage.script` は必須（無いと `OYASAIBAN_IMPORT_ERROR missing_storage_script`）。`storage.log`（未反映の追加・削除）と `usercache.json` は任意で、あれば使います。
- 取り込むのは `BAN` と `TEMP_BAN` だけです。`IP_BAN`・`KICK` などは数えますが取り込みません。
- 有効 BAN は、すでに期限切れのもの、OyasaiBan 側に有効 BAN がある相手のものを飛ばします（既存は置き換えない）。履歴は「UUID・種別・開始時刻」が同じものを重複として飛ばします。何度 `run` しても二重には入りません。
- UUID 欄に名前しかない行は、`usercache.json` → Mojang の公開 API の順で解決します。解決できなかった名前は1件ずつログに出て、結果には件数だけが出ます。その行は取り込まれません。
- 結果は `AdvancedBan import run: active 新規/走査 new, history 新規/走査 new, unresolved 件数.` と、機械向けの `OYASAIBAN_IMPORT …` の2行です。走査件数には取り込まない種別も含みます。失敗時は `OYASAIBAN_IMPORT_ERROR failed`（`run` は全体を巻き戻す）。
- **名前の照会中は DB の処理が止まり、その間のログインと BAN コマンドは待たされます**（1件あたり最大で十数秒）。未解決の名前が多いときは、人の少ない時間に実行してください。
- 取り込んだ名前は「記録した名前」として最新扱いで保存されます。AdvancedBan 時代の古い名前で `/check` などが当たるようになり、その人が次にログインするまで現在の名前の記録が上書きされます。

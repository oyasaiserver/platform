# DynamicProfile の運用（運営向け）

プレイヤー向けの操作は [player.md](player.md)、実装の入口と技術仕様は [PROJECT.md](PROJECT.md) を参照してください。

DynamicProfile はプロフィール・統計・レベル・称号・おすすめ建築・リーダーボードを管理します。ランク昇降格、報酬、送金などは LuckPerms、Vault、TokenManager、SocialLikes3 などの連携先も使います。

## 権限

| 権限 | plugin.yml の既定値 | できること |
|---|---|---|
| `dprofile.basic` | true | `/dprofile`、リーダーボード、おすすめ登録。各コマンドは別名を含めて同じ権限 |
| `dprofile.op` | 記載なし | `/dpmanager`（別名 `/dpma`・`/dpm`） |
| `oyasai.syokaku` | op | `/syokaku` の全サブコマンド |
| `oyasai.syokakumanager` | op | `/syokakumanager loadpast` |

`dprofile.op` の permission 定義には `default` がありません。サーバー側の権限設定を確認してください。昇格系サブコマンドに個別の権限はなく、コマンド定義の権限が適用されます。

`/dp` とリーダーボード、おすすめコマンドはプレイヤー権限で使用します。`/dpmanager` は多くのサブコマンドをコンソールから実行できますが、`save`、`chest`、称号一覧・称号所有者・プレイヤー称号のGUIはゲーム内プレイヤーが必要です。`/syokaku` の実行はコンソールにも対応しています。ただしコンソールで昇降格すると、実行者名（例: `CONSOLE`）が履歴に保存されます。履歴表示は実行者を UUID として解析するため、その記録のチャット表示・GUI表示は例外で失敗します。履歴表示が必要な操作はゲーム内プレイヤーから実行してください。

## 管理コマンド

### `/dpmanager`

| サブコマンド | 動作・注意 |
|---|---|
| `reloadConfig` | `config.yml`、`groups.yml`、`receiveStatus.yml` を再読込します。表示は「dpをコンフィグにリロードがしたよ。（日本語不自由）」です。 |
| `save` | 実行したプレイヤーの統計を SQLite の書き込みキューへ追加します。コンソールでは「このコマンドはプレイヤーから実行してください。」と表示します。 |
| `updateLB` | `LeaderBoards/latest.json` を日時付き JSON に移し、週間集計を空にします。メモリ上の未保存分は保存せず破棄するため、退避ファイルにも入りません。実行者への完了表示はありません。 |
| `required <経験値>` | `basicRequired` を変更します。0・負数も受け付けますが、処理が終わらなくなる場合があるため正数にしてください（式と上限は下記）。 |
| `beh <種類> <値>` | 行動ごとの獲得経験値を変更します。実際に受け付ける種類は `Move`、`Vehicle`、`Fly`、`Jump`、`Block`、`Vote`、`Like`、`ReceiveLike`、`Join` です。 |
| `noticeLvs <レベル>` | 指定レベルを全体通知の対象に追加・削除します。 |
| `chest` | 3ブロック以内で見ているチェストを、レベル報酬用チェストに指定します。チェスト以外を見ていると処理されません。コンソールでは実行できません。 |
| `receiveStatus <レベル|*>` | 指定レベル、または `*` の全レベルについて報酬受取記録をリセットします。 |
| `title list` | 全称号をGUIに表示します。プレイヤーのみ。 |
| `title owners <称号ID>` | 称号所有者のGUIを表示します。プレイヤーのみ。 |
| `title player [プレイヤー名]` | プレイヤーの所有称号GUIを表示します。名前省略時は実行者。プレイヤーのみ。 |
| `title add <名前> <優先度>` | 称号を作成します。 |
| `title give <プレイヤー> <称号ID>` / `title deprive <プレイヤー> <称号ID>` | 称号を付与・剥奪します。すでに所有・未所有の場合は状態を変えず、その旨を返します。 |
| `title edit <称号ID> <名前>` / `title editDesc <称号ID> <説明...>` | 称号名・説明を変更します。 |
| `title remove <称号ID>` | 称号を削除します。 |
| `title get <称号ID>` | 称号名を表示します。 |
| `title reload` | 現在のメモリ上の称号をファイルへ保存してから読み直します。外部編集したファイルを先に読み込む用途ではありません。 |
| `setCount <UUID> <BehType> <数>` | 統計カウンターを置き換えます。即時保存の呼び出しはありません。 |
| `repair <UUID>` | `recoverfiles/<UUID>.json` の経験値と移動・飛行・乗り物・ジャンプ・設置・チャット・投票・いいね双方・参加カウントだけを現在値へ加算します。プレイ時間、距離の端数、おすすめ、紹介文、称号、友達、昇格履歴は復旧しません。再実行すると重ねて加算します。ファイルがなければ処理に失敗します。即時保存の呼び出しはありません。 |
| `setEmpty` | 全ユーザーのおすすめ欄にある旧値 0 / -1 を空欄値へ変え、変更したプロフィールを保存します。 |
| `recommendInterval [秒]` | 宣伝間隔を表示・変更します。1以上の整数が必要です。変更時は宣伝タスクを再起動します。 |
| `recommendMode [BUILDING_FIRST|PLAYER_FIRST|HYBRID]` | おすすめ紹介モードを表示・変更します。設定後すぐ反映されます。 |
| `setSpecialFrameInterval [回数]` | 特別枠の間隔を表示・変更します。1以上が必要です。値は次回の宣伝タスク起動時に読み直します。 |
| `kakonoEXP kakutei` | SocialLikes3 のいいね利用者と建築所有者を対象に、既存の統計・経験値再計算処理を開始します。補完候補には出ません。対象を二分して非同期に処理するため、事前にデータを退避し、実行後の値を個別確認してください。 |

`beh` の入力候補には `Chat` と `PlayTime` も出ますが、このサブコマンドの処理分岐はこの2種類を受け付けません。値は整数として解析されます。空引数や不正な数値は、コマンドによってはエラーになります。

称号の作成・付与・剥奪・編集はメモリ上の状態を変更し、通常の実行中は即時に `Titles.json` へ保存しません。停止時には保存されます。`title reload` は先にメモリ上の状態でファイルを上書きします。

### `/syokaku` と `/syokakumanager`

| コマンド | 動作 |
|---|---|
| `/syokaku getrank <プレイヤー>` | LuckPerms の所属グループから、`ranks.json` にあり最も grade の高いランクを表示します。 |
| `/syokaku iscandidate <プレイヤー>` | 次ランクの条件（総プレイ時間、ログイン日数、初回参加からの日数、SocialLikes3 建築数）と達成状況を表示します。 |
| `/syokaku seerequirements <ランク名>` | `ranks.json` にあるランクの条件を表示します。 |
| `/syokaku seeplayerinfo <プレイヤー>` | ランク・昇格日・参加・建築などの概要を表示します。追加引数にページ番号または `gui` を指定すると昇格履歴を表示します。 |
| `/syokaku promote <プレイヤー> [備考...]` | 条件達成時に次のランクへ昇格します。条件未達でも、備考部分が大文字 `GOOD` で始まる場合は特例として実行できます。 |
| `/syokaku demote <プレイヤー> [備考...]` | 現在のランクを外し、ひとつ前のランクを付与します。最低ランクからは降格できません。 |
| `/syokakumanager loadpast` | LuckPerms の `parent add` を昇格履歴として取り込みます。`ranks.json` にないグループ追加も対象です。降格は復元せず、プレイ秒数・レベル・経験値は0で記録します。既存履歴との重複を判定しないため、再実行すると履歴が重複します。 |

現在ランクは、`ranks.json` に対応する継承グループのうち最も grade が高いものです。昇格は次のグループを追加します。降格は現在グループを削除し、前のグループを追加します。昇格・降格はプロフィールの履歴にも記録します。昇格時には Move カウントへ100を加算します。Discord webhook が設定され、ランク名が解決できると通知を送ります。

昇格条件のログイン日数は `Stats.join` です。参加処理時に前回加算日時との差を判定し、通常は24時間以上経過していれば1回加算します（初回は加算）。暦日の切替や長時間オンラインによる日ごとの加算ではありません。

## 設定と既定値

`plugins/DynamicProfile/config.yml` に含まれる値です。数値はコード内の読み出し値を基準にしています。

| キー | 同梱設定の既定値 | 用途 |
|---|---:|---|
| `Move` | 20 | 徒歩移動のカウントごとの経験値 |
| `Vehicle` | 20 | 乗り物移動のカウントごとの経験値 |
| `Fly` | 10 | 飛行移動のカウントごとの経験値 |
| `Jump` | 40 | ジャンプごとの経験値 |
| `Block` | 20 | ブロック設置ごとの経験値 |
| `Vote` | 30000 | 投票ごとの経験値 |
| `Like` | 4000 | いいねごとの経験値 |
| `ReceiveLike` | 6000 | いいねを受けたときの経験値 |
| `Join` | 10000 | 参加日の加算ごとの経験値 |
| `Chat` | 300 | チャットごとの経験値 |
| `PlayTime` | 300 | 1分ごとのプレイ時間加算の経験値 |
| `noticeLvs` | `[]` | 全体へレベルアップを通知するレベル |
| `basicRequired` | 1000 | レベル必要経験値の基本値 |
| `RewardChestXYZ` | `[0.0, 0.0, 0.0]` | 報酬チェストの座標 |
| `RewardChestWorld` | `world` | 報酬チェストのワールド名 |
| `RecommendBroadcastIntervalSeconds` | 600 | おすすめ建築紹介の間隔（秒） |
| `RecommendBroadcastMode` | 0 | 0=建築優先、1=プレイヤー優先、2=両方を順に分散 |
| `specialFrameInterval` | 3 | 特別枠を何回ごとに出すか |
| `webhook-url` | 未設定 | 昇格・降格の Discord 通知先。旧設定から移す場合の条件は下記参照 |

初期設定ファイルのコメントには `Vehicle: Default 10`、`Like: Default 3000` とありますが、設定値はそれぞれ20、4000です。実行時の値はファイルの設定が使われます。

コード側の補助値・ファイルも確認してください。

- `maxRequired` は同梱 `config.yml` にありません。未設定時の上限は70000です。
- `basicRequired` のコード内フォールバックは2000ですが、同梱設定値は1000です。`/dpmanager required` は `basicRequired` を変更します。次レベルへの必要経験値は `min((現在レベル + 4) × basicRequired, maxRequired)` です。両方とも正数にしてください。正値の検査はなく、必要経験値が0以下になる設定ではレベル計算が終了しなくなる場合があります。
- `Required` はコマンドクラスで読み込まれますが、参照されません。レベル計算に使われる設定ではありません。
- `groups.yml` はレベルに応じて LuckPerms グループを追加する対応表です。初回は空の YAML として作成されます。レベルアップ時にコンソールから `lp user <名前> parent add <グループ>` が呼ばれます。
- 報酬チェストでは、鉄インゴットの表示名を `レベル,金額`、金インゴットを `レベル,ポイント数`、石炭を `レベル,マイル数` として読み取ります。シュルカーボックスとその他のアイテムはアイテム報酬です。こちらも表示名のカンマより前を整数レベルとして読みます（例: `10,報酬`。`10` だけでも有効）。通常の名前のままでは整数に変換できず、スキップしてログに警告します。
- 同じレベルの報酬はまとめて付与し、`receiveStatus.yml` にレベル単位で受取済み UUID を保存します。後から同レベルの報酬を追加しても、受取済みの人は受け取れません。`/dpmanager receiveStatus <レベル|*>` は指定レベルの全員の記録を消すため、既存報酬の再受取にも注意してください。
- 経済・ポイント API が未取得でも付与を飛ばして受取済みに進みます。Vault の付与結果やマイル付与コマンドの戻り値も確認しません。例外で処理が中断した場合は受取済みの保存まで進まないため、一部だけ付与済みになる可能性もあります。障害時は連携先の実残高と受取記録を照合してください。
- ギフトの記録には、同梱設定にない `giftRecordWorld` と `giftRecordWorldChestXYZ` が参照されます。コード側にワールド名の既定値はありますが、公開資料には記載しません。座標の既定値はありません。記録先をローカル設定で明示し、座標が正しいチェストを指すことを確認してください。設定がない場合、ギフトの送信後に記録処理が失敗する可能性があります。
- `RecommendBroadcastMode` はコード上 0、1、2 を受け付けます。`specialFrameInterval` は宣伝器の起動時に取得され、設定変更だけでは稼働中の値が変わりません。変更後は宣伝タスクの再起動かサーバー再起動が必要です。1未満は管理コマンドで拒否されますが、設定ファイルから直接指定した値は検査されません。0では紹介処理の剰余計算が失敗します。

`webhook-url` は Discord 通知オブジェクトの初期化時に読み出して保持します。初期化後は `reloadConfig` だけでは変更を反映しません。URLを変更したらサーバーを再起動してください。

### おすすめ紹介の選出

対象はおすすめ登録済みのオンラインプレイヤーです。最初は特別枠で、以降は `specialFrameInterval` 回ごとに特別枠になります。Vault のグループ照会で `donator` / `spdonator` に属する人が特別枠の対象です。対象不在なら通常枠（登録済みのオンライン全員）へ戻ります。

- `BUILDING_FIRST`: 対象者の建築から未紹介 ID をランダムに選び、対象がなくなると建築キャッシュを消します。
- `PLAYER_FIRST`: 未紹介プレイヤーからランダムに選び、対象がなくなるとプレイヤーキャッシュを消します。建築はその人の登録分からランダムに選びます。
- `HYBRID`: 未紹介プレイヤーを選び、その人の未紹介建築を選びます。その人の建築がすべて既出なら枠の建築キャッシュ全体を消します。全建築が一巡するまで重複しない保証はありません。

キャッシュは特別枠と通常枠で別です。削除済み・不正な ID は選出時に除外せず、紹介の建築名が `null` になる場合があります。

## データの保存場所

| 場所 | 内容・注意 |
|---|---|
| `plugins/DynamicProfile/dynamicprofile.db` | SQLite。プロフィール統計と昇格履歴、初回 JSON 取込の状態・失敗ファイル名 |
| `plugins/DynamicProfile/UserStatsJSON/` | 旧プロフィール JSON。DB 初回取込後も削除・変更されません。 |
| `plugins/DynamicProfile/Titles.json` | 称号定義と所有者。JSON。 |
| `plugins/DynamicProfile/LeaderBoards/latest.json` | 週間集計の保存済みデータ。行動に伴いメモリ上で自動加算しますが、週次の自動リセットはありません。`updateLB` はこのファイルだけを退避し、未保存分を破棄します。 |
| `plugins/DynamicProfile/LeaderBoards/<日時>.json` | 期間切替時の `latest.json` のコピー。切替直前のメモリ上の全集計ではありません。自動削除されません。 |
| `plugins/DynamicProfile/config.yml` | 経験値、報酬チェスト、おすすめ紹介などの設定。 |
| `plugins/DynamicProfile/ranks.json` | 昇格ランク定義。 |
| `plugins/DynamicProfile/groups.yml` | レベル別 LuckPerms グループ設定。 |
| `plugins/DynamicProfile/receiveStatus.yml` | レベル報酬の受取記録。 |
| `plugins/DynamicProfile/recoverfiles/<UUID>.json` | `repair` が読む復旧用統計ファイル。 |

`ranks.json` の各項目は `name`、`groupName`、`grade`、`minPlayTimeHours`、`minJoinDays`、`minElapse`、`minBuilds`、`special` です。`Rank.kt` の宣言値は `grade`、条件の各数値が0、`special` がfalseです。`name` と `groupName` に既定値はありません。ファイルがない、または空ならランク一覧は空です。ランク一覧は遅延初期化され、`reloadConfig` では読み直されません。編集後はプラグインを再起動してください。

## 起動・移行・障害時

### 初回起動と旧データ

1. DynamicProfile は `config.yml` の既定値を作り、旧昇格データの引き継ぎを行います。
2. DP 側に `ranks.json` がなく、隣の `OyasaiAdminTools` データフォルダに同ファイルがある場合だけコピーします。
3. DP 側の `config.yml` に `webhook-url` キーがない場合だけ旧設定から値をコピーします。空文字が明示されている場合は DP 側の値を優先します。元ファイルは変更・削除しません。
4. SQLite に `UserStatsJSON/*.json` を取り込むのは、取込完了印がなく、プロフィール表が空の場合です。取込と完了印は同じトランザクションで確定します。
5. 元 JSON は残ります。新規取込時は `Imported <成功数> player JSON files; <失敗数> failed. Original JSON files retained.`、取込済みでは `Legacy JSON import already completed; loading SQLite.` が記録されます。最後に `Loaded <件数> player profiles from SQLite` を確認してください。

初回取込は、JSON フォルダや対象ファイルがない場合、または全ファイルの読み込みに失敗した場合も完了印を記録します。その後 JSON を追加・修正しても自動再取込しません。SQL の失敗はトランザクションを戻して完了印を残さず、次回起動時に再試行します。別のプロフィール行が既にある DB では、未取込でも JSON を読み込まず完了印を記録します。

### 障害時の表示とログ

- DB 初期化・読み込みに失敗すると `Failed to initialize profile database` をログに出し、プラグインを無効化します。旧 JSON へ自動で切り替えません。
- DB 書き込み失敗は `Failed to save profile data: ...` としてログに出ます。メモリ上の変更は巻き戻らず、保存成功にもなりません。停止時の DB クローズも保留中の書き込みを待ち、書き込み失敗を呼び出し元へ返します。
- 読めない旧 JSON はファイル名だけ警告され、他のファイルの取込は続きます。UUID 名の失敗は DB に記録され、対象プレイヤーの参加時に本人と OP へ通知されます。本人には「エラーが発生したため、あなたのDynamicProfileの情報が一時的に初期化されています。管理者に連絡してください。」、OP には「[DynamicProfile] プレイヤー <名前>(<UUID>) のデータ読み込みに失敗しています。管理者はUserStatsJSON/<UUID>.jsonを確認してください。」と表示されます。元ファイルを確認し、必要な復旧を行ってください。保存・修復コマンドは失敗記録を消しません。
- 正常停止ではプロフィール書き込みキューを完了させてから DB を閉じます。DB の自動バックアップ、旧 JSON への逆変換、失敗記録の解除機能はコードにありません。移行前にデータフォルダを退避してください。

### 保全される範囲・保証されない範囲

**コードで保証する処理**

- プロフィールと同じプレイヤーの昇格履歴は1つの SQLite トランザクションで保存します。書き込みキューに渡す前にプロフィール値と可変コレクションをスナップショットします。
- 旧 JSON の初回取込と取込完了印は同じトランザクションです。壊れたファイルは個別に記録して読み飛ばし、元 JSON は変更しません。
- DB 終了処理はキュー済み書き込みを待ちます。失敗があれば記録されます。

プロフィールの定期保存はありません。通常の行動、毎分のプレイ時間、紹介文、おすすめ、通知設定、称号選択は基本的にメモリ更新です。退出・投票・明示保存・正常停止などの保存機会までの変更は、異常終了時に失われ得ます。週間集計のファイル保存は正常停止時で、プロフィールの `save` や退出では保存しません。`updateLB` は未保存分を失うため、保全が必要な切替前には正常停止して保存を確認し、データフォルダを退避してください。

**保証しない処理**

- DB・JSON・YAML をまとめた自動バックアップはありません。SQLite から旧 JSON への自動ロールバックもありません。
- 書き込み失敗後もメモリ上の統計変更、LuckPerms 変更、Vault・TokenManager の送金や報酬、SocialLikes3 の建築データを一括で巻き戻す処理はありません。
- おすすめ建築は SocialLikes3 の ID を保存します。ID変更や建築削除で参照が不正になっても自動修復・削除しません。紹介に `null` が出る場合などは元の建築IDと所有者を確認し、本人におすすめの解除・再登録を依頼してください。
- プレイヤーGUI、権限、各連携先との実サーバー動作は、この資料作成時に確認していません。

## 他プラグインとの連携

| 連携先 | plugin.yml の指定 | DynamicProfile が使う機能 |
|---|---|---|
| Votifier | 必須依存 | 投票イベントを統計・経験値へ加算 |
| Vault | 必須依存 | 経済 API、権限グループ照会 |
| TokenManager | 必須依存 | 所持ポイント表示・報酬（送金は外部コマンドを呼出） |
| SocialLikes3 | softdepend | 建築一覧・ID・いいね・所有者・建築数・テレポート先 |
| LuckPerms | softdepend | 昇格ランク、権限グループ照会、レベル別グループ追加 |
| OyasaiMenu | plugin.yml に依存指定なし | `Tools.validatedTitle` と `Calculator.getLevel` で選択称号・レベルを表示 |

外部コマンドとして `/pay`、`/token send`、`/tpa`、`milepoint add` を呼びます。各コマンドの有効性や権限は連携先側の設定に依存します。Discord 通知は `webhook-url` が設定され、昇降格ランクが `ranks.json` から解決できる場合に送信します。

# OyasaiMenu の運用（運営向け）

プレイヤー向けの操作は [player.md](player.md)、開発・実装の案内は [PROJECT.md](PROJECT.md) を参照してください。ゲーム内での動作確認は未実施です。

## 権限

| 権限・設定 | 既定 | 対象 |
|---|---|---|
| `oyasaimenu.use` | OP | `/menu`、`/shop`、`/pointshop`、`/sell` |
| `oyasaimenu.admin` | OP | `/adminmenu`、`/menuedit`、`/oyasaimenu` |
| `save.menu.item` | プラグイン側の既定値は未定義 | `/savemenuitem`。plugin.yml のコマンドにはこの権限が指定されていますが、permissions 節に既定値の宣言がありません。サーバー上の実効値は未確認です。 |
| なし | 権限指定なし | `/getmenu`。ゲーム内専用です。 |

- `oyasaimenu.use` と `oyasaimenu.admin` の既定値はいずれも plugin.yml の `default: op` です。通常ユーザーへ使わせる場合はサーバー側の権限設定が必要です。
- `oyasaimenu.use` はコマンド入口の権限です。通常ショップ・ポイントショップ・売却 GUI を開く処理やクリック処理では確認しません。メニューアクションからの遷移や、画面を開いた後の権限剥奪も、この権限だけでは取引を止められません。
- `/adminmenu` はコマンド定義に加えて画面を開く処理でも管理権限を確認します。開いた後のリロードボタンでは権限を再確認しません。
- `/menuedit` の実行はコマンド定義の権限で制限します。ハンドラとタブ補完処理には独自の権限確認がありません。
- メニュー YAML の `permission` は `lpgroup:<group>` 形式にも対応し、LuckPerms の primary group または権限判定を使います。Popup YAML の `required_permission` は Bukkit の `hasPermission` で判定し、`op_only` は OP かどうかで判定します。両方あると `required_permission` が優先されます。

## 管理コマンド

| コマンド | 用途・挙動 |
|---|---|
| `/adminmenu` | 管理画面を開きます。リロードと、ショップ・売却ホワイトリスト管理コマンドの案内があります。ゲーム内専用です。 |
| `/oyasaimenu` | バージョンとヘルプを表示します。 |
| `/oyasaimenu reload` | config と各 YAML を読み直します。権限がない場合は「リロード権限がありません。」、成功時は「リロード中...」の後に「OyasaiMenu をリロードしました。」を表示します。 |
| `/menuedit shop <category> list` | ショップカテゴリの商品を一覧表示します。 |
| `/menuedit shop <category> add <material> <buy> <sell>` | 素材名と買値・売値を追加します。素材名は Bukkit Material 名で検証します。 |
| `/menuedit shop <category> remove <index>` | 商品を削除します。番号は1始まりで、空行とコメント行を数えません。一覧に出ない不正行があると、一覧番号と削除対象がずれる可能性があります。 |
| `/menuedit whitelist list` | 売却ホワイトリストの登録内容を表示します。 |
| `/menuedit whitelist add hand <price>` | メインハンドのアイテムを登録します。売値は正の数で、手にアイテムが必要です。 |
| `/menuedit whitelist remove <index>` | 売却ホワイトリストを削除します。番号は1始まりです。 |
| `/savemenuitem` | メインハンドのアイテムをメニュー用アイテムとして保存します。ゲーム内専用で、アイテム種別の検証はありません。 |
| `/getmenu` | 保存済みのメニュー用アイテムを受け取ります。未登録でも「You have received menu item!」と表示しますが、アイテムは渡りません。 |

ショップ編集では、買値・売値の文字列を数値として読めることを確認して保存します。読み込み時は有限値かつ0以上の価格だけが有効です。0は有効な設定値ですが、その方向の取引はできません。負値や非有限値は追加コマンドが受け付けた後、再読み込み時にスキップされる場合があります。編集コマンドの保存に失敗した場合もログへ警告を出しますが、コマンドは成功したように表示されることがあります。操作後はログと再読み込み後の一覧を確認してください。不正行があるカテゴリでは、表示一覧と削除コマンドの番号が一致しない可能性があります。

`/menuedit whitelist add hand` は、登録済みアイテムと同じコンポーネントのアイテムを重複登録できません。比較時は個数・耐久値・lore を無視するため、それらだけが違うアイテムも重複扱いです。カスタム名のないアイテムには注意メッセージが出ます。売値は0以下を拒否しますが、有限値チェックはありません。NaN と正の Infinity はこの検査を通り登録されます。ホワイトリスト照合でその価格を取得した場合、NaN は `/sell hand` の入金処理から Vault へ渡りますが、`/sell all` と売却 GUI ではそのアイテムを対象から外します。正の Infinity はこれら3経路で Vault へ渡ります。Vault provider の応答は未確認です。

売却処理がホワイトリストを参照するのは、カスタム名、本のタイトルまたはページ（BookMeta で判定するため、ページのある署名前の本と羽根ペンも含む）、カスタムモデルデータを持つアイテムです。エンチャントやポーション効果だけのアイテムはカスタム品として判定されず、`/sell` 系では素材ごとの通常ショップ価格で処理します。容器の中身や任意の PDC も保護条件ではありません。カスタム名など上記条件のない中身入りシュルカーボックスは、同梱の素材売値で売却対象になり、中身ごと失われます。ホワイトリストの保存に失敗した場合もログに警告が出ますが、画面上は追加・削除が成功したように表示されることがあります。

メニューアイテムは `/savemenuitem` 時点の個数を含めて保存し、初回参加者にはその個数で配ります。`/getmenu` は1個だけ配ります。空の手も保存できますが、AIR テンプレートでは起動しません。起動とクラフト制限の照合は `ItemStack.isSimilar` で行うため、個数以外の名前・メタデータなどを変えると一致しなくなる場合があります。起動時はメインハンドを確認します。

`/menuedit` はゲーム内専用です。メニュー本体、Popup、ポイントショップ、カスタムアイテム定義を編集するコマンドはありません。これらはデータファイルを編集してからリロードします。

## 設定と既定値

### config.yml

| 項目 | 同梱時の既定値 | 現在のコードでの扱い |
|---|---:|---|
| `menu.default` | `root` | `/menu` で最初に開くメニュー ID です。 |
| `placeholders.server-name` | `OyasaiServer` | 現在のコードから参照されていません。変更しても表示には使われません。 |
| `cooldown.click-ms` | `100` | 通常メニュー・Popup・通常ショップ・ポイントショップ・管理画面のクリック間隔です。売却 GUI には適用しません。5種類で UUID ごとの記録を共有するため、画面遷移直後も無言でクリックを無視する場合があります。0以下で無効です。設定値が欠けている場合のコード上の既定値は200です。 |
| `cooldown.command-ms` | `300` | `/sell hand` と `/sell all` の連続実行を抑えます。0以下で無効です。コード上の既定値も300です。 |
| `sell-whitelist.enabled` | `true` | 現在のコードでは参照されません。ホワイトリスト機能の有効・無効は切り替えません。 |

### データファイル

すべてプラグインのデータフォルダ内に保存されます。初回起動時に同梱リソースから不足ファイルを作ります。既存ファイルは `/oyasaimenu reload` で上書きされません。

| ファイル | 用途・既定値 |
|---|---|
| `config.yml` | 上記の設定。`saveDefaultConfig` で不足時のみ作られます。 |
| `menus/root.yml` | `/menu` の既定画面。標準ではお知らせとプロフィール、各メニューへの入口があります。 |
| `menus/popup/*.yml` | チャンネル、売却、ショップ一覧、SocialLikes、CarBuilder、ユーティリティ、リンク集、バイオーム選択などの画面です。標準の8ファイルは不足時に再配置します。 |
| `menus/shop/shops.yml` | 通常ショップの商品と買値・売値。初期カテゴリは blocks、decorations、ores、tools です。商品行は `<material> <buy> <sell>`、カスタム商品は `$<key> <buy> <sell>` です。 |
| `menus/shop/custom_items.yml` | 通常ショップ用カスタム商品。素材、表示名、説明、エンチャントを定義します。 |
| `menus/shop/pointshop.yml` | ポイントショップの商品、費用、購入メッセージ、実行コマンドです。費用が1未満の行は警告して読み飛ばします。同梱の point1 のキー15・16は費用0のため読み込まれません。 |
| `announcements.yml` | `announcements` リストの先頭要素だけを読み込みます。タイトルと本文はルートメニューに表示します。 |
| `sell-whitelist.yml` | 特殊アイテムの売値。存在しない場合は空の `entries: []` を作ります。アイテムデータは Base64 化した Bukkit のシリアライズデータです。 |
| `command-items.db` | `/savemenuitem` で保存したアイテム。SQLite の `command_items(name TEXT PRIMARY KEY, item BLOB NOT NULL)` に `menu` という名前で保存します。 |

### メニュー定義の既定値

- 通常メニュー YAML は `menu.title`（省略時 `&8メニュー`）、`menu.size`（省略時54）と `items` を持ちます。size は9〜54に制限し、9の倍数へ切り上げます。item の slot は省略時0、icon は `STONE`、name は空、lore/actions は空、permission/texture は未指定、enchanted は false です。未知のアイコンは `STONE`、`AIR` は空欄になります。
- 通常メニューに同じ slot を複数定義しても検証されません。画面構築時に同じスロットへ順に item を置き、表示条件を満たし実際に配置された後の定義で上書きします。一方、クリック処理は最初の定義を選んでから AIR・権限を判定するため、表示と実行内容が一致しない、または反応しない場合があります。Popup でもクリックは最初の定義です。重複 slot は作らないでください。`menu:` セクションがない YAML は読み込みに失敗します。root が読み込めない場合は空の root 画面、他の ID では「メニューが見つかりません: <ID>」になります。
- Popup YAML は title の省略時にファイル名、glass の省略時に `GRAY_STAINED_GLASS_PANE`、nav_active の省略時に -1 を使います。ナビバー用の slot 45〜53 は警告して読み飛ばし、0〜44 の外は画面に配置しません。権限条件を満たさない項目は fallback_icon / fallback_item / fallback_actions に従います。
- PointShop の item は icon の省略時に `CHEST`、close-on-purchase の省略時に false です。cost の省略値は0で、その項目は読み飛ばされます。商品名 `name` は `%player%` だけ、`lore` は `%player%`、`%tokens%`、`%price%`、`%balance%` を置換します。購入 message では player/tokens/price、実行 commands では player/price を置換します。

通常ショップ価格の読込時は、有限値で0以上の買値・売値を受け付けます。不正な価格や未定義のカスタム商品はスキップされ、素材名が不明な通常商品は表示できない状態で読み込まれます。カスタムショップ商品の表示名・説明・エンチャントは GUI 表示に使われますが、購入処理が作るアイテムには素材とエンチャントだけが設定されます。

ショップ行の重複は拒否されません。通常売却用の価格 map は素材ごとに1件を保持し、読み込みで後から処理された売却可能な行が同じ素材の値を上書きします。`/sell hand`、`/sell all`、売却 GUI の価格はこの素材単位の map を使います。通常ショップ画面から商品を売る場合は、その画面の商品行の価格を使います。素材一致、`getSellPrice` が null でないこと、通常エンチャントの種類・レベルが商品定義と完全一致することが必要です。`/sell` 系では商品行とのエンチャント一致は求めません。エンチャント付き商品でも購入だけが1個固定で、通常売却は数量ボタン、Shift 売却は一致する所持品すべてが対象です。重複行を作らないでください。カスタムアイテム定義で不明な素材は警告後に STONE となり、不明なエンチャントは警告後に読み飛ばされます。

売却ホワイトリストの比較では個数・耐久値・loreを無視し、素材、カスタム名、通常エンチャント、保存エンチャント、本のタイトル・著者・ページ数、カスタムモデルデータ、ポーション種別・効果を比較します。本の本文、名前の色・装飾（プレーンテキストで比較）、任意の PDC、容器の中身は比較しません。登録品と本文や任意データまで同一であることは保証しません。ホワイトリストの保存失敗は警告ログのみで、メモリ上の変更は戻りません。再起動後に変更が消える可能性があります。

### YAML のアクションと表示を編集する

通常メニューは `actions: [{type: OPEN_MENU, target: root}]` のような type と引数の形式です。`OPEN_SHOP` は `category`、`PLAYER_CMD` は `command` を使います。`RUN_COMMAND` / `CONSOLE_CMD` はコンソール実行です。通常メニュー・Popup とも `OP_PLAYER_CMD` / `op_player_cmd` は現在 OP の人だけ実行でき、一時的に OP を付与しません。対応する全 type と引数は [PROJECT.md のアクション設定契約](PROJECT.md#アクション設定契約) を参照してください。

通常メニューの title/name/lore とテキスト系アクションの対応プレースホルダー一覧は [PROJECT.md のメニューとアクション](PROJECT.md#メニューとアクション) を参照してください。lore の `%announcement_body%` は単独要素として書きます。

Popup は `actions: [{player_cmd: spawn}]` のようなキー形式です。title/name/lore はプレースホルダー置換しません。action value の `%player%` は `player_cmd`、`console_cmd`、`op_player_cmd`、`suggest_command` だけで置換します。`url` / `chat_paste` はそのままチャットへ表示します。`close`、`suggest_command`、`op_player_cmd` を含む列は次 tick に閉じ、その次 tick にコマンド・遷移を実行します。それ以外は閉じずに次 tick に実行します。URL・チャット表示は閉じる前、その場で送ります。

Popup の `item` / `fallback_item` は素材・個数・ブロック状態と、ポーション・通常エンチャント・保存エンチャントの対応項目だけを適用します。任意の Minecraft コンポーネントは適用しません。権限不足時の未指定 fallback はガラス埋め、`fallback_icon: AIR` は空欄ですが、いずれも `fallback_actions` があれば実行できます。通常側が `icon: AIR` かつ `item` 未指定なら fallback を含めてクリックしません。`fallback_item` の優先順位、重複 slot と AIR の消去処理、設定例は [PROJECT.md の Popup 設定契約](PROJECT.md#popup-設定契約) を参照してください。

## 起動・リロード・障害時

- 起動時にメニューアイテム用 SQLite を開き、その後メニュー・ショップ・Popup・お知らせ・売却ホワイトリストを読み込みます。SQLite を開けない場合はメニューアイテム機能だけを無効にし、残りのプラグインは起動します。ログには「Command item storage failed to start; command items are unavailable.」が出ます。
- `/savemenuitem` の SQLite 保存に失敗した場合は「アイテムの保存に失敗しました。」を表示し、ログにエラーを出します。保存に失敗しても、すでにメモリ上に読み込まれているアイテムは更新しません。初回参加者への配布や `/getmenu` の持ち物あふれ分はプレイヤーの位置に落とします。
- Vault 経済サービスが見つからない場合は通常ショップと売却が使えません。TokenManager が見つからない場合はポイントショップが使えません。DynamicProfile が無い、または表示情報の取得に失敗した場合、レベル表示は `---` になります。
- `/oyasaimenu reload` は設定、各メニュー・ショップ・Popup、お知らせ、売却ホワイトリスト、経済・ポイント連携、クールダウンを再初期化します。メニューアイテム用 SQLite は開き直しません。通常メニュー画面は閉じますが、他の GUI をすべて閉じる処理ではありません。
- 各ローダーはファイル単位・行単位で不正データを警告して読み飛ばすものがあります。その場合もリロードコマンドは最後に成功メッセージを返すことがあるため、起動・再読み込みの警告とロード件数を確認してください。
- お知らせ YAML が空、または解析に失敗した場合は現在のメモリ上の表示を消去せず、前の内容を保持します。
- ファイル形式の移行処理はありません。SQLite はテーブルがなければ作成しますが、旧形式を変換する処理はありません。編集や復元の前に該当データをバックアップしてください。

## 守られる範囲と守られない範囲

- 通常メニュー、Popup、ショップ、ポイントショップ、管理画面では、GUI 上段のクリックをキャンセルします。売却 GUI は入力用の上段枠を操作でき、閉じると未売却品をプレイヤーへ返します。
- クリエイティブ制限はショップ・売却コマンドの受付時と通常ショップの商品画面・売却画面を開く時に確認します。各 GUI のクリック処理でゲームモードを再確認しないため、画面を開いた後にモードを変えた場合の売買は制限されません。ゲーム内挙動は未確認です。ポイントショップにはゲームモード判定がありません。
- 多くの GUI エンジンに InventoryDragEvent の処理はありません。コードだけではドラッグ操作の結果を確認できないため、GUI 内のアイテム移動を安全に防げるとは扱わないでください。ゲーム内での確認は未実施です。
- メニューアイテムは右クリックでメニューを開き、作業台クラフトに含まれた場合はクラフトをキャンセルします。ドロップ、保管、取引、その他のアイテム使用を止める処理はありません。
- YAML の `console_cmd` とポイントショップの商品コマンドはコンソールから実行します。呼び出し元のプレイヤー権限を引き継がず、実行結果や付与成功も検査しません。設定ファイルを編集できる人を制限してください。
- ポイントショップは購入時にポイントを差し引いてから商品コマンドを実行します。コマンドが失敗しても返金処理はありません。
- 通常ショップの入金・引き落とし結果は Vault API の成否を確認します。売却入金に失敗した場合はアイテムを残すか戻します。購入後に所持品へ入りきらない分は地面に落とします。

## 他プラグインとの連携

| 連携先 | 用途 | 利用できないとき |
|---|---|---|
| Vault と Vault Economy provider | 通常ショップの残高、引き落とし、入金 | 通常ショップと売却を停止します。 |
| TokenManager | ポイント残高とポイント引き落とし | ポイントショップを停止します。残高取得の API 失敗は警告して0として扱います。 |
| LuckPerms | メニュー項目の権限・グループ条件 | 取得失敗時は Bukkit の権限判定へフォールバックします。 |
| DynamicProfile | メニュー内のレベル・タイトル表示 | 無効または取得失敗時は `---` を表示します。 |

plugin.yml の softdepend は LuckPerms、DynamicProfile、TokenManager、Vault です。メニュー定義から他プラグインのコマンドを実行しますが、そのコマンドが存在するか、実行に成功したかは OyasaiMenu では保証しません。

# DirectState の運用（運営向け）

プレイヤー向けの操作は [player.md](player.md)、実装の詳細は [PROJECT.md](PROJECT.md) を参照。

## 権限

| 権限 | 既定 | できること |
|---|---|---|
| `directstate.ds` | OP | 全機能。子権限として以下を付与 |
| `directstate.dsh` | なし | 素手編集モードの設定と利用 |
| `directstate.dsr` | なし | 素材置換モードの設定と利用 |
| `directstate.dsu` | なし | 個人の更新抑制モードの設定 |
| `directstate.gettool` | なし | 編集棒を受け取る、または手持ちアイテムを編集棒にする |
| `directstate.stick` | なし | Hand 編集棒の使用 |
| `directstate.sstick` | なし | シンプル棒の使用 |
| `directstate.hstick` | なし | ホールド棒の使用 |

`directstate.ds` は上記の全権限を子として持ちます。コマンドはプレイヤー専用で、コンソールからは使えません。`/ds` と `/ds gui` は設定画面を開きますが、表示される設定項目は各機能の権限に応じて変わります。`/ds help` と `/ds toggle` は全機能の権限を確認します。運営専用の別コマンドはありません。GUI の一括停止項目は `directstate.dsh`・`directstate.dsu`・`directstate.dsr` の3権限が揃えば表示されます。`directstate.ds` のないプレイヤーでも GUI では一括停止でき、`/ds toggle` は拒否される場合があります。

## コマンド

| コマンド | 権限 | 動作 |
|---|---|---|
| `/ds`, `/ds gui` | なし（プレイヤーのみ） | 設定画面を開く |
| `/ds help [1\|2\|3]` | `directstate.ds` | 3ページのヘルプ |
| `/ds toggle`, `/ds tgl` | `directstate.ds` | 素手編集・更新抑制・素材置換を一括停止／再開 |
| `/ds hand [on/off/toggle]`, `/dsh [on/off/toggle]` | `directstate.dsh` | 素手編集の設定 |
| `/ds update [on/off/toggle]`, `/dsu [on/off/toggle]` | `directstate.dsu` | 個人の更新抑制設定 |
| `/ds replace [on/off/toggle]`, `/dsr [on/off/toggle]` | `directstate.dsr` | 素材置換の設定 |
| `/ds replace type [off/strict/compatible]`, `/dsr type` または `/dsr tp` | `directstate.dsr` | 形の合わせ方を順送り、または指定 |
| `/ds stick [set]` | `directstate.gettool` | Hand 編集棒を渡す／手持ちを変換 |
| `/ds sstick [set]` | `directstate.gettool` | シンプル棒を渡す／手持ちを変換 |
| `/ds hstick [set]` | `directstate.gettool` | ホールド棒を渡す／手持ちを変換 |

`set` なしでは、インベントリに空きがある場合だけ棒を渡します。`set` はメインハンドのアイテムへ種類識別の PDC だけを付与します。通常発行のホールド棒に付く `CONSUMABLE`・`FOOD` データは追加しません。元アイテムが長押し使用できなければ、`isHandRaised` が必要なホールド編集は同等に動作しません。棒を配布する権限と、棒を使う権限は別です。

## 設定と既定値

プラグイン設定ファイルはありません。プレイヤーごとの初期値は次のとおりです。

| 設定 | 既定 | 保存範囲 |
|---|---|---|
| 素手編集 (`handEnabled`) | OFF | プレイヤーごと |
| 個人の更新抑制 (`updateEnabled`) | OFF | プレイヤーごと |
| 素材置換 (`replacementEnabled`) | OFF | プレイヤーごと |
| 形の合わせ方 (`typeReplacementMode`) | `OFF` | プレイヤーごと |
| アイテム不要モードの一括停止 (`itemlessModesDisabled`) | OFF | プレイヤーごと |
| WorldGuard の `directstate-no-updates` | 未設定時は抑制しない | 領域ごと。`ALLOW` のみ抑制 |

一括停止は、素手編集・個人の更新抑制・素材置換を止めます。個別設定値は変更しません。編集棒の使用と WorldGuard の領域フラグはこの一括停止の対象外です。

素材置換の `OFF` は素材ファミリーによる形の検索を無効にします。置換時には、置換先が受け入れる BlockData プロパティが個別に引き継がれることがあります。`STRICT` は同じ形のファミリーを探し、`COMPATIBLE` は壁・フェンス・板ガラス間の対応形状も探します。該当する形を解決できない場合は手持ち素材へ置換します。

形の解決に成功し、同素材の相方があるドア・ベッドだけは2ブロック一緒に置換します。通常置換・フォールバックは1ブロックだけです。解決後の置換先素材が元と同じなら、状態の変換前に終了します。Replace OFF または一括停止中は Type 設定が `STRICT`／`COMPATIBLE` でも動作せず、状態メッセージの末尾に `(inactive)` が付きます。

素手・棒・Replace の直接編集には、素材消費もサバイバル／クリエイティブ限定の判定もありません。Replace はアイテムの種類だけを読み、個数を減らしません。強制配置との違いを踏まえて権限を配布してください。編集道具を持つ間の破壊と、道具として印を付けた食べ物の消費はキャンセルされます。

## データと起動

- プレイヤー設定は `plugins/DirectState/users.db`（SQLite）の `player_settings` テーブルに保存されます。UUID ごとに5項目を保存します。
- ブロック状態は専用データベースではなく、ワールド上のブロック状態として変更します。編集棒の種類はアイテムのデータに記録されます。更新ガード、ドラッグ中の状態、ボタンの復帰予約はメモリ上だけです。
- 起動時にデータフォルダを作成し、DB を開いてテーブルを作成（なければ）し、設定をメモリへ読み込みます。プラグインは `sqlite-jdbc` をサーバーライブラリとして宣言しています。
- `config.yml`、`paper-plugin.yml`、別プラグインからの設定・保護データ移行処理はありません。DB は `CREATE TABLE IF NOT EXISTS` で初期化されますが、既存テーブルの列を追加するスキーマ移行はありません。
- UUID として読めない行は読み飛ばし、未知の形状モード文字列は `OFF` として読み込みます。既存テーブルに必要な列がない場合、起動時の SELECT は失敗します。
- 設定変更のたびに SQLite へ同期的に書き込みます。書き込みが失敗すると変更値をメモリへ反映せず、エラーを呼び出し元へ返します。専用の自動バックアップや復旧処理はありません。
- データフォルダを作れない場合、DB を開けない場合は初期化に失敗します。起動ログと SQLite のファイル・権限・ディスク状況を確認してください。

## 更新抑制の範囲と注意

個人設定が ON で必要な権限がある場合、またはプレイヤーの現在地にある WorldGuard 領域で `directstate-no-updates: ALLOW` の場合に有効です。領域フラグが `ALLOW` なら、個人設定 OFF・一括停止中・`directstate.dsu` 権限なしでも有効です。WorldGuard の判定位置は編集対象ではなくプレイヤーの位置です。WorldGuard の連携は更新抑制だけで、建築・編集権限の判定ではありません。

編集元の周囲2ブロック以内にある読み込み済みの非空気ブロックを記録し、編集元とその周囲を4tickだけガードします。ガード中は物理更新、ブロック破壊イベント、落下ブロック化、液体移動、レッドストーン出力、ピストン、ディスペンサー、振動、燃焼・延焼、生成・融解・成長、TNT 着火、物理・閉塞による額縁等の破壊など、実装済みのイベントを抑制します。

保存したブロックと現在の素材が同じで、状態だけが変化した場合はガード中に保存状態へ復元します。空気や別素材を戻す一般的なロールバックではありません。

有効中の通常操作にも次の変更があります。

- 設置直後の看板編集画面（設置を理由に開く場合）をキャンセルします。
- 感圧板・トリップワイヤー・踏み荒らし等の `PHYSICAL` 操作を拒否します。
- レバー・ボタン等の Switch とドア等の Openable を更新なしで切り替えます。編集道具を使う場合、先行処理でブロック操作が拒否されている場合、アイテムを持ってしゃがんでいる場合は対象外です。ドアは同素材の相方も開閉します。ボタンは木製30tick、その他20tick後に、押下後の状態が変わっていない場合だけ戻します。
- ベッドを壊して相方が空気になった場合、チャンクが読み込まれていれば次tickに相方だけを復元します。
- 有効なプレイヤー由来の振動と TNT 着火は、4tick の周辺ガードがなくても拒否します。

この機能はワールド全体や領域全体を恒久保護するものではありません。爆発専用イベントなど、登録されていない更新は対象外です。ブロックの保護機能として運用しないでください。

## 強制配置と保護プラグイン

Update Mode 中は、通常配置が支持条件などで拒否される一部のブロックについて、強制配置経路が動くことがあります。サバイバルまたはクリエイティブのみを対象にし、サバイバルで成功した場合はアイテムを1個消費します。高さ、チャンク読込、ワールド境界、スポーン保護、エンティティとの衝突を確認します。`BlockCanBuildEvent` を呼び、配置後は `BlockPlaceEvent` または `BlockMultiPlaceEvent` を発火します。イベントが拒否された場合は配置前の状態へ戻します。通常のブロック操作を持つブロックでは、しゃがんでいるときなどを除き、バニラ操作を優先します。

強制配置は支持不足のほか、昆布・海草、上下の面をクリックした吊り看板、置換可能ブロックをクリックした看板でも明示的に選ばれます。看板以外で `BlockStateMeta`・`SkullMeta`・`BannerMeta` を持つアイテムは強制配置しません。看板は両面の文字・色・発光とワックスをコピーしますが、PDC 全体はコピーしません。

共通のブロック編集は、WorldGuard の建築権限や他の保護プラグインの権限 API を直接照会しません。通常の編集イベントは先にキャンセルされた `PlayerInteractEvent` を無視しますが、保護プラグインごとのイベント処理に依存します。直接編集は通常の `BlockPlaceEvent`／`BlockBreakEvent` を発火しないため、配置・破壊イベントだけを監視する保護・監査プラグインが検知できるとは限りません。強制配置は共通編集サービスのログ集約・ActionBar 表示を通らず、CoreProtect の記録も配置イベントの監視に委ねます。一般編集と強制配置の両方を、実際の保護プラグイン構成で確認してから権限を配布してください。

## 他プラグインとの連携

- **CoreProtect:** 有効な API v10 以上（CoreProtect 22.4 以上）を検出した場合、DirectState の直接編集を除去・設置・`DirectState` 操作のログとして記録します。同じプレイヤー・座標の連続編集は最後の編集から40tick後にまとめて記録し、使用終了・持ち替え・手の交換・ログアウト時はそのプレイヤーの保留ログを即時確定し、プラグイン停止時は全員分を確定します。移動・外部変更・権限喪失・視線角度等によるホールドの内部終了では即時確定せず、原則として最後の変更から40tick後に確定します。CoreProtect 不在、API 非対応、記録失敗でもブロック編集は止まりません。連携障害の警告は最初の一度だけです。
- **WorldGuard:** `onLoad` で `directstate-no-updates` の StateFlag を登録し、領域で `ALLOW` の場合に更新抑制を有効にします。同名の互換 StateFlag があれば再利用します。別種の同名フラグや登録失敗はログを確認してください。登録時の `IllegalStateException` は完全なサーバー再起動を求めるログになります。
- **FastAsyncWorldEdit:** `softdepend` に含まれますが、DirectState から FAWE API を呼ぶコードはありません。ブロックエンティティの表示状態を扱う部分は Paper/Purpur の内部クラスをリフレクションで操作します。

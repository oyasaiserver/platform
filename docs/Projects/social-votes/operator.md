# SocialVotes の運用（運営向け）

プレイヤー向けの操作は [player.md](player.md)、実装の入口と技術仕様は [PROJECT.md](PROJECT.md) を参照してください。

## 権限

| 権限・条件 | 既定 | コード上の扱い |
|---|---|---|
| `socialvotes.use` | 全員 | 定義されていますが、SocialVotes の処理では参照されません。投票・GUI・通常コマンドの許可判定には使われません。 |
| `socialvotes.admin` | OP | `/svupdate` と、移設モード中のクリック時に確認されます。 |
| OP | OP | `/sv delhere`・`/sv allclear`、グループオーナー権限の代行などで `isOp` が確認されます。権限ノードを付与しただけでは OP 判定の代わりになりません。 |
| 看板の制作者 | 作成者 UUID | 簡易GUIで看板名・制作者の編集ができます。 |
| グループオーナー | グループ作成者 UUID | グループの看板追加・除外、投票開始・終了、詳細GUIを利用できます。 |

- `/sv` のサブコマンド、投票、看板登録には `socialvotes.use` の確認がありません。グループ操作などはコマンド処理内でオーナーまたはOPかを個別に確認します。
- 管理操作の多くはコンソールから実行できません。`/sv` は引数なしなら使用方法を表示しますが、引数を付けた操作、`/svupdate`、`/svtp` はプレイヤー専用です。
- `/sv remove` は誰でも操作待ち状態に入れますが、看板をクリックした時点でグループオーナーまたはOPか確認されます。
- 詳細GUIを開く時点ではグループオーナーまたはOPか確認されますが、詳細GUI内の各操作では再確認しません。権限を変更した場合は、開いたままのGUIを閉じてください。

権限で拒否されたときの表示は次のとおりです。

| 操作 | 表示 |
|---|---|
| `/sv add` の看板クリック | `この操作はグループ作成者またはOPのみ可能です。`（アクションバー） |
| `/sv startvote` | `§cこの操作はグループ作成者またはOPのみ可能です。` |
| `/sv stopvote` | `§cこの操作はグループオーナーのみ可能です。` |
| `/svupdate` | `§cこの操作には管理者権限が必要です。` |
| `/sv allclear`・`/sv delhere` | `§cOPのみ実行できます。` |
| 看板名・制作者編集 | `§c制作者またはOPのみ操作できます。` |

## 管理コマンド

| コマンド | 条件・動作 |
|---|---|
| `/sv setgroup <name>` | プレイヤーがグループを作成し、作成者をオーナーにします。同名グループがあると `既にそのグループは存在します。` と表示します。 |
| `/sv add <group>` | グループオーナーまたはOPが使えます。操作待ちの後、登録看板を右クリックすると追加します。1グループ45看板までです。 |
| `/sv remove` | 登録看板を右クリックしてグループから外します。看板クリック時にオーナーまたはOPを確認します。看板がなくなってもグループは自動削除されません。 |
| `/sv list [group]` | グループ一覧、またはグループの看板名・ID・座標を表示します。グループ名を知っていれば、オーナーでないプレイヤーも個別一覧を要求できます。個別一覧の看板行は `/svtp <id>` を実行するクリックリンクです。 |
| `/sv startvote <group>` | グループオーナーまたはOPが開始時刻を現在時刻に設定します。既存の終了時刻が現在時刻以前なら解除し、未来なら保持します。 |
| `/sv stopvote <group>` | グループオーナーまたはOPが終了時刻を現在時刻に設定します。開始時刻未設定、または開始前は `§c投票はまだ開始されていません。` で拒否します。 |
| `/sv allclear <group>` | OP専用。グループ内の登録看板を削除し、グループを消します。登録先ワールドが読み込まれている場合、看板の登録座標にあるブロックも削除対象です。 |
| `/sv delhere` | OP専用。プレイヤー自身の現在のブロック座標にある登録を削除します。看板を見て実行するコマンドではなく、現在位置のブロック座標を参照します。 |
| `/svupdate` | `socialvotes.admin` が必要です。移設元のSV看板が持つ登録IDを使って座標を移します。移設後の看板がそのIDを保持している状態で、メインハンドで右クリックします。IDを持たない新しい看板は対象になりません。 |
| `/svtp <id>` | プレイヤーが登録看板の座標へ移動します。対象ワールドが読み込まれていなければ移動できません。 |

`/sv help` には `/sv list`、`setgroup`、`add`、`remove`、`startvote`、`stopvote` が表示され、OPには `allclear` と `delhere` も表示されます。`/svtp` と `/svupdate` はこのヘルプには載りません。

## GUIでの管理

登録看板をしゃがみながら右クリックすると簡易GUIが開きます。看板制作者またはOPは看板名・制作者表示を変更し、制作者を追加・削除できます。グループオーナーまたはOPは「詳細設定」から次を実行できます。

- 看板・グループの得票表示を切り替える。
- 看板・グループの1人あたり投票上限を設定する。
- グループの開始時刻・終了時刻を設定する。
- 全プレイヤーの看板票、またはグループ票をリセットする。
- 看板を削除する、またはグループと所属看板を完全削除する。

上限・時刻・名前などの入力はチャットの次の1メッセージを使い、そのメッセージは通常チャットに流れません。期限や明示的なキャンセルコマンドはありません。看板/グループ全体の削除は登録座標のブロックも消す場合があるため、対象と座標を確認してください。

## 設定項目と既定値

`config.yml` などの設定ファイルはありません。次の値は新規データの既定値で、看板やグループの詳細GUI、または保存データから変わります。

| 対象 | 項目 | 既定値・動作 |
|---|---|---|
| 新規看板 | 名前 | 作成時の看板2行目。コード上の `SVSign` は行が `null` の場合の既定値です。 |
| 新規看板 | 制作者 | 看板を作ったプレイヤー1人の UUID |
| 新規看板 | 制作者表示名 | 未設定。複数制作者なら表示名は `制作者多数`。 |
| 新規看板 | 得票数 | `0` |
| 新規看板 | 得票表示 | 公開 |
| 新規看板 | 1人あたり看板上限 | `1` 票 |
| 新規看板 | 所属グループ | なし |
| 新規看板 | 作成時刻 | 登録した時点の現在時刻 |
| 新規グループ | オーナー | 作成したプレイヤーの UUID |
| 新規グループ | 登録看板 | なし。追加上限は45看板。 |
| 新規グループ | 1人あたりグループ上限 | `1` 票 |
| 新規グループ | グループ得票表示 | 公開 |
| 新規グループ | ソート値 | `id`。この値は現在の結果GUIでは参照されません。 |
| 新規グループ | 開始・終了時刻 | どちらも未設定（常時投票可能） |

- 投票時は看板上限とグループ上限のうち有効な小さい値を看板ごとの上限として使い、さらにグループ全体の票数も確認します。保存値が0以下ならその上限判定は行われませんが、GUIから設定できる値は正の整数のみです。
- 看板単体の上限をグループ上限より大きく設定することはできません。グループ上限を下げると、所属看板の上限も新しいグループ上限まで切り下げられます。
- グループ得票表示の切替は、グループ内の全看板の看板表示設定にも反映します。その後、看板単体の表示を切り替えることはできます。
- 時刻入力は日本時間です。`0` で解除します。実装上、`d` と `h` を含む入力が必要で、年・月・分は省略できます。範囲外の数値を拒否する検証はなく、形式不正時は変更せず通知もしない場合があります。

## 保存場所とデータ形式

- 保存先は `plugins/SocialVotes/data.yml` です。SQLiteや外部データベースは使いません。
- 主な項目は `signs.<id>`（ワールド名・座標・名前・制作者・票数・表示・上限・グループ・作成時刻）、`groups.<name>`（看板ID・オーナー・上限・表示・開始/終了時刻）、`playerVotes.<group>.<UUID>`、`playerVotesPerSign.<id>.<UUID>` です。
- 看板ブロックには Persistent Data Container に整数の看板IDも記録します。座標と投票データは `data.yml` が正本で、起動時に読み込んだ看板のうち、その時点でワールドが読み込まれているものだけを座標検索表へ登録します。
- データファイルがない場合は、空のデータを保存して起動します。旧フォルダや旧形式からのコピー・変換処理はありません。スキーマ版や自動バックアップもありません。
- 削除後の看板IDは、空いている最小の正整数から再利用されます。ワールドが未読み込みのため物理看板が残った状態でIDが再利用されると、古い看板のPDCが新しい登録IDを指す可能性があります。

## 起動・移行・保存失敗時

- `onEnable` はコマンド・イベントを登録する前に `data.yml` を読み込みます。読み込み例外をプラグイン側で捕捉して復旧する処理はありません。
- 制作者UUIDの不正値は読み飛ばされます。制作者が全員無効なら `Sign <id> has no valid creators.` を警告し、制作者なしの看板として読み込みます。看板ID、グループオーナーUUID、投票者UUIDなどの不正値は変換例外を捕捉しません。
- `data.yml` の保存は同期処理です。ゲーム内の投票・編集などでメモリ上の値を変えた後に直接 `yaml.save` します。保存失敗の捕捉、プレイヤーへの失敗通知、メモリの巻き戻しはありません。失敗時のファイル状態やサーバー側の継続動作は実環境で未確認です。
- プラグイン停止時にも `save()` を呼びます。停止時の保存例外も捕捉されません。
- 看板登録は看板へのID記録とメモリ更新を行った後に保存します。`/svupdate` は座標変更を保存した後に移設先看板へIDを記録します。いずれも書き込み失敗時に前の状態へ戻す処理はありません。
- 移行前に `data.yml` をバックアップしてください。旧データとの自動移行機能はないため、別形式からの変換はコード外で計画する必要があります。

## 看板の保護範囲

- 登録看板への通常の破壊イベントをキャンセルします。看板編集画面を開くイベントもキャンセルします。OPにも例外を設けていません。
- 看板を支えるブロックの破壊は、床看板の下、壁看板の背面、天井吊り看板の上をキャンセルします。壁吊り看板は支えブロックを保護しません。
- 保護処理は主に `BlockBreakEvent` と `PlayerSignOpenEvent` に限られます。爆発、ピストン、ワールド編集、他プラグインによる直接変更などを止める処理はありません。
- 看板を登録した時点の座標に別のブロックを置き換えてから登録を削除すると、その座標のブロックも `AIR` にされます。削除前に登録座標とワールド状態を確認してください。
- ワールドが起動時に未読み込みだと座標検索表へ登録されません。ワールド読み込み後の再構築処理はありません。この場合、看板編集・破壊の保護が効かない可能性があります。

## 他プラグインとの連携

- `paper-plugin.yml` に他プラグインの `depend` / `softdepend` はありません。SocialVotes 固有の外部APIも公開していません。
- Bukkit Services の登録はありません。`ChatInput.start/cancel` などの公開メソッドはありますが、他プラグインからの利用箇所や互換性保証はリポジトリ内で確認できません。
- ビルド時は Purpur API を `compileOnly` で参照します。ゲーム内イベント、Persistent Data Container、コマンド、インベントリGUIは Bukkit/Paper API を使います。
- コマンド登録時にサーバー実装の `commandMap` フィールドへリフレクションでアクセスします。フィールド名・アクセス制限が変わった環境での動作は未確認です。

## 障害・運用上の注意

- 得票表示の「非公開」は看板上の得票行だけを隠します。グループ詳細GUIから開く投票結果・投票者一覧には得票数と投票者名が表示されます。
- 操作待ち（看板追加・除外・移設）とチャット入力には期限がありません。プレイヤー切断時の解除処理は登録されていないため、再接続後に状態が残る可能性があります。サーバー/プラグイン再起動ではメモリ上の状態が消えます。
- `/sv allclear` と詳細GUIのグループ完全削除は、看板ごとの票記録を消しますが、グループ単位の `playerVotes` を明示削除しません。同じグループ名を再作成した場合、残ったグループ票が上限判定に影響する可能性があります。
- `/sv remove` で所属看板をすべて外しても空グループは残ります。空グループの自動削除は、個別看板削除から呼ばれる処理に限られます。

# EntityPose の運用（運営向け）

プレイヤー向けの操作は[player.md](player.md)、実装の案内は[PROJECT.md](PROJECT.md)を参照してください。

## 権限

| 権限 | 既定 | できること |
|---|---|---|
| `entitypose_arrange` | OP | `/ep` の全コマンドと、権限チェックのある道具操作を使う |

- `plugin.yml` では `/ep` にこの権限が設定され、権限の既定値は `op` です。
- 運営専用の別コマンドはありません。運営もプレイヤーと同じ `/ep` コマンドを使います。
- コマンド実行時にプレイヤー以外から送ると、何も表示せずに終了します。コンソールから管理する方法はありません。
- `/ep` の実行時と多くの道具操作では権限を確認します。一方、設定画面やスポーン選択画面のクリック処理は権限を再確認しません。画面を開いた後に権限を外しても、画面から行う設定変更などが実行される場合があります。スポーンした追従中エンティティを右クリックで固定する処理は権限を再確認します。
- 個別設定画面のクリック処理は、クリック時に視線先をray traceしますが、そこで対象がプレイヤーか、AIが有効か、操作権限があるかを再確認しません。設定画面を開いた後に別のプレイヤーへ視線を向けて操作すると、そのプレイヤーに設定が付く可能性があります。

## 管理操作

管理専用コマンドはなく、権限を持つプレイヤーが標準コマンドを使います。

| 対応 | 方法 |
|---|---|
| 対象情報を確認 | `/ep info` → 対象を見る |
| 対象の設定を変更 | `/ep infoset` → 対象を見ながら画面をクリック |
| 不要な範囲選択を解除 | `/ep clear` |
| 範囲を複製 | Copy Wandで両端を選び、`/ep copy` → 移動先で `/ep paste` |
| 選択中のエンティティを削除 | `/ep cut`。確認画面・取り消し機能はない |

全コマンドと画面の説明は[プレイヤー向けガイド](player.md)を参照してください。

## 設定項目と既定値

プラグイン設定ファイルはありません。以下はコードにある動作値で、設定ファイルから変更する項目ではありません。

| 項目 | 既定値・範囲 | 保存・変更 |
|---|---|---|
| 角度の刻み | 初期値1度。コマンド入力は0.5〜90度に制限。画面選択肢は1、5、8、12、15、22.5、40、45度 | プレイヤーごとのメモリ上の値。ログアウト時に消去。`/ep kakudo [数値]` |
| 移動量の刻み | 初期値1マス。コマンド入力は0.01〜2マスに制限。画面選択肢は0.1、0.25、0.5、1マス | プレイヤーごとのメモリ上の値。ログアウト時に消去。`/ep zahyo [数値]` |
| スケール | 読み取り時、属性がない場合の代替値は1.0。設定範囲0.3〜3.0、0.1単位 | エンティティのスケール属性。`/ep scale 数値` または設定画面 |
| 空中足場 | OFF | プレイヤーごとのメモリ上の切替。`/ep hojo on|off`。有効時、条件を満たす操作でガラスを置き、プレイヤーが水平に1.1ブロック以上離れるかオフラインになると空気に戻す |
| スポーン画面の追従距離 | 2.5ブロック | 固定値。エンティティ棒で選んだプレビューを毎tick移動 |

## データの保存場所

- `plugins/EntityPose/` に設定ファイル、独自DB、独自の保存ファイルを作る処理はありません。
- 道具の識別情報と、ダメージ無効・アレンジロック・アイテムロック・死亡時のドロップ抑制などは、アイテムまたはエンティティの Persistent Data Container に記録します。位置・向き・装備などはエンティティ本体の状態を変更します。実際の保存タイミングはワールドのエンティティ保存に依存し、ゲーム内での再起動確認は未実施です。
- 反転表示の対象UUIDはメインスコアボードの `animal_things_hide_name` チームに登録されます。起動時に同名チームがなければ作成し、既存の場合も表示名設定を `NEVER` にします。
- 名前非表示チームのUUIDエントリは、チャンクUNLOADでは残し、それ以外のエンティティ削除時に除去します。残存エントリの調査では削除原因を確認してください。
- エンティティ棒の右クリック編集とプレビュー確定は `isPersistent = true` を設定しますが、Pasteはこのプロパティを明示設定しません。設置と貼り付けの保存・消失条件は同じとは限らず、実機では未確認です。
- コピーは通常名、動物の透明状態、年齢固定、懐いた動物の所有者を復元しません。子供かどうかと懐き状態は復元しますが、生成時に固定した子オオカミ・子ネコの年齢固定も復元しません。詳細は `commands/EntityCopy.kt`、`EntityCopyData.kt`、`commands/EntityPaste.kt` を参照してください。
- 角度・移動量、範囲の端点、選択対象、Copy/Pasteのクリップボード、追従中エンティティ、足場モードなどはメモリ上の状態です。サーバープロセスの再起動で失われます。プラグインだけを再読み込みした場合の状態は未確認です。プレイヤーのログアウト時には角度・移動量・範囲・部位選択を消しますが、クリップボードはログアウト時に消去しません。
- 範囲選択やクリップボードに期限切れ処理はありません。足場モードもログアウト時に消去されず、同じプレイヤーが再ログインすると有効状態が残る場合があります。サーバープロセスの再起動時には初期値のOFFに戻ります。
- 範囲の端点は座標だけでワールド名を保持しません。選択後にワールドを移動すると、移動先ワールドで以前の座標を使う可能性があります。移動前に `/ep clear` を実行してください。

## 起動・移行・障害時の注意

- 起動時は NamespacedKey を初期化し、`/ep` の実行先を登録し、メインスコアボードのチームを取得または作成して、イベントリスナーを登録します。初期化やスコアボード取得の独自リカバリ処理はありません。
- 旧バージョンのファイルや別プラグインからの移行処理はありません。データベース移行もありません。EntityPoseのキー名やプラグイン名前空間を変える場合、既存のエンティティ・アイテムの記録を変換する処理はコードにありません。
- 追従中にプレイヤーがログアウトすると、ログアウト処理から `FollowEntity.stop` が呼ばれます。コード上はプレビューを消さず、LivingEntityを永続化し、AIと重力を無効にした状態で残します。誤って生成したプレビューをログアウトで取り消す動作ではありません。
- コピーはメモリ上のみです。EntityPose再起動後はクリップボードを復元できません。範囲選択から `cut` したエンティティを戻す仕組みもありません。
- 一時足場は、足元が空気の場合にガラスへ変更してメタデータを付けます。除去時はそのメタデータが残っていればブロックを空気にします。設置後に別の処理が同じ場所のブロックを変更した場合も、コードは現在のブロック種類を確認してから消すわけではありません。建築物の保護機能として扱わないでください。
- 足場OFFは新規設置を止めるだけで、既存ガラスは距離・オフライン条件による除去を待ちます。停止時の一括撤去もありません。距離計算はワールド一致を確認せず、オフライン判定より先に行うため、ワールド移動後に除去が失敗する懸念があります。実際の例外・残留は未検証です。作業後は同じワールドで離れて撤去を確認し、停止前にも残ったガラスを確認してください。
- GUI用プレイヤーヘッドのテクスチャ設定で例外が起きると、スタックトレースを出して処理を続けます。表示欠けのほか、スポーン自体の失敗に対する独自の復旧処理やエラーメッセージはありません。
- EntityPoseはワールド保存失敗を検出・再試行する独自ストレージを持ちません。バックアップとワールド保存の運用はサーバー側で行ってください。

## 守られる範囲・守られない範囲

- ダメージ無効の印があるエンティティは `EntityDamageEvent` をキャンセルします。死亡そのものを防ぐ機能ではありません。プレビュー確定とPasteは死亡時のドロップ抑制の印も付けます。この印がある対象の死亡時は装備を含むドロップ・経験値が消えます。装備は死亡前に回収してください。この印はエンティティの削除や `/ep cut` を止めません。
- アレンジのロックはエンティティ棒での選択・調整を止めるための機能です。範囲移動ではロック済み対象を除外しますが、スケール設定、設定画面の操作、コピー、削除を一律に禁止しません。エンティティ全般の保護機能として扱わないでください。
- 個別設定GUIの開始時にはプレイヤーを拒否しますが、GUIの各クリック時は現在の視線先を再検索し、他のプレイヤーを除外しません。権限を持つ利用者にGUIを開かせる場合は、他プレイヤーが照準に入らない位置で操作させてください。
- アイテムのロックは、アーマースタンドの装備操作イベントをキャンセルします。ブロック保護やエンティティの削除防止ではありません。
- EntityPoseは領域保護、権限領域、クレームを照会しません。エンティティの生成・移動・削除操作に他プラグインの領域ルールが適用される保証はありません。コードはイベントのキャンセル状態を一律に確認せず、イベントリスナーの多くに `ignoreCancelled = true` がありません。
- 道具を持つスロットへの切替で始まる照準表示は、約5ブロック以内の生き物の `isGlowing` を直接変更します。利用者だけへの表示ではなく、元の発光状態を退避せず解除時にfalseにするため、複数利用者や他プラグインの発光と干渉する可能性があります。
- `animal_things_hide_name` という既存チームがある場合は再利用し、表示名の可視性を変更します。同名チームを使う別機能がある場合は競合する可能性があります。

## 他プラグインとの連携

- `plugin.yml` に `depend` / `softdepend` はありません。外部プラグイン向けAPIやWorldGuard等との明示的な連携は実装されていません。
- ビルド時のコンパイル依存は Purpur API のみです。EntityPoseはメインスコアボードとBukkit/Paperイベントを利用します。
- 起動時にメインサーバーへ入れる Nix package は、[PROJECT.md](PROJECT.md)のAI作業入口を参照してください。

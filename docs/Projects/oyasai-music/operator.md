# OyasaiMusic の運用（運営向け）

操作は [player.md](player.md)、技術仕様と実装の入口は [PROJECT.md](PROJECT.md) を参照。
以下は2026-10-12のコード確認と2026-10-13のレビュー指摘の再照合による仕様です。起動・移行・クライアントの音声再生は実機で未確認です。

## 導入と権限

Paper側は `plugin.yml` の `api-version: 26.2`、`load: POSTWORLD`。FastAsyncWorldEditが必須です。コンパイル対象はPurpur開発バンドル26.2、FAWE 2.15.3です。対応する最小FAWEバージョンの実機確認はしていません。
同じ `OyasaiMusic.jar` にPaper／Velocityの入口が入ります。Velocityは曲を保存せず通信を中継し、統合版パックの許可情報は保存します。

| 権限 | 既定 | 用途 |
|---|---|---|
| `oyasaimusic.admin` | OP | 管理コマンド、審査GUI、他人の楽曲設定、他人への音楽プレイヤー配布 |
| `oyasaimusic.use` | false | `/mm`、`/getmp` のコマンド受付 |
| `oyasaimusic.record` | false | `/record`（終了・検査も含む） |
| `oyasaimusic.demosound` | false | `/demosound` |
| `oyasaimusic.import` | false | OMMTのアップロード受付。各段階で再確認 |
| `oyasaimusic.notify` | false | 初回通常公開・リポストのチャット通知と効果音 |
| `oyasaimusic.record.range.16` | false | 環境BGMの最大半径16 |
| `oyasaimusic.record.range.64` | false | 同64（16以下も含む） |
| `oyasaimusic.record.range.256` | false | 同256（64以下も含む） |
| `oyasaimusic.record.range.world` | false | ワールド全体、任意の数値範囲 |

`false` は権限宣言の既定値です。管理権限だけでは一般コマンドの権限を代替しません。コードにはOP直接判定や範囲権限の子ノード宣言がなく、範囲は持っている権限の最大値以下を実装で許可します。数値の絶対上限は30,000,000です。
携帯プレイヤーの右クリック・GUI内の通常操作・レコード設置で `oyasaimusic.use` を再確認する処理はありません。設定画面は作者または管理権限を確認しますが、録音差し替えのGUIは `oyasaimusic.record` を確認しません。コマンド権限だけで全入口を封じることはできません。

## 管理操作

| 操作 | コマンド・手順 |
|---|---|
| 設定再読込 | `/oyasaimusic reload` |
| 前日・前週ランキングの再集計 | `/oyasaimusic update`（開始を通知。完了通知ではない） |
| パック許可／停止 | `/oyasaimusic rp set <player\|uuid>` / `unset <player\|uuid>` |
| パック保存値・接続状態を確認 | `/oyasaimusic rp check <player\|uuid>` |
| Paperに保存されたALLOW一覧 | `/oyasaimusic rp list [page]`。1ページ10人、ページ番号1〜100,000 |
| 音楽プレイヤー配布 | `/getmusicplayer <player>`（別名 `/getmp`）。オンラインの完全一致名 |
| 曲の編集・削除 | IDで `/mm open <ID>` → 楽曲設定。管理権限は個人再生の制限を自動で迂回しない |
| オリジナル審査 | `/mm` →「審査・履歴管理」 |

`rp` は `resourcepack` でも可。管理コマンドはコンソールから実行できます。`/mm`・`/record`・`/demosound` はプレイヤー専用です。`/getmp` の非プレイヤー送信者は宛先が必要です。配布時はインベントリの余りを処理せず、満杯でも成功表示になり得ます。

審査一覧は通常公開または限定公開で、申請時刻があるか下書き以外の審査状態を持つ曲です。全下書きの一覧ではありません。
左クリックは審査用試聴（個人再生のアクセス制限を迂回し視聴数を加算しない）、Shift＋左は詳細。右は仮OK → 許可 → 未審査 → 却下 → 許可、Shift＋右は同じ曲で2回操作して却下します。右クリックによる却下には追加確認がありません。判定は公開状態を変えず、作者がオンラインなら通知します。未審査へ戻しても申請時刻は消えないため、作者の再申請が通るとは限りません。

## 設定項目と既定値

Paperの `plugins/OyasaiMusic/config.yml`。既定ファイルの値と実装を照合しています。URL・ホスト名を含む値は公開規則に従って転記せず、同梱設定・パーサーを参照します。

| キー | 既定値 | 内容・境界 |
|---|---|---|
| `storage.database-file` | `database.db` | プラグインデータフォルダからの相対パス。設定コメントの「pluginsフォルダから」は実装と異なる |
| `storage.audio-directory` | `audio` | 同フォルダからの相対ディレクトリ |
| `recording.default-price` | `1000` | 新規下書き価格 |
| `recording.default-record-material` | `MUSIC_DISC_13` | 新規下書きのレコード種類。表示・購入では解決できない素材を13へ代替 |
| `playback.lookahead-ms` | `35` | 0〜50に補正。現行の通常送音カーソルは経過時刻までを送る。旧説明の「先読み送音」と同一ではない |
| `playback.view-limit-per-hour` | `3` | 同じ人・同じ曲の直近3600秒の計上上限。0以下なら計上しない |
| `playback.view-limit-per-day` | `10` | 同86400秒の計上上限。0以下なら計上しない |
| `playback.views-per-point` | `10` | 累計視聴数がこの倍数になったとき、収益化対象作者へ1pt。0以下はポイント加算なし |
| `economy.like-reward-money` | `1000` | いいね送信者へ即時入金。負値は0へ補正 |
| `economy.like-reward-points` | `2` | 作者の未受取ポイント。負値は0へ補正 |
| `economy.record-sale-author-share` | `0.8` | 有料購入額×比率を整数に切り捨て。比率自体の範囲検証なし、負の還元額は保存側で0へ補正 |
| `bedrock.name-prefix` | `.` | Paperでの統合版判定は名前の接頭辞だけ。空なら検出しない |
| `bedrock.chord-limit` | `3` | 同時刻・同楽器の音数がこの値以上なら旧 `pitch` の最小・最大へ間引き。拡張音域では通常域へ折り畳んだ値で選ぶため、本来の最低・最高音とは限らない。下限補正なし |
| `bedrock.mcpack-url` | 空文字 | 既定ファイルにあるが、実装で参照しない |
| `bedrock.mcpack-sha1` | 空文字 | 同上 |
| `bedrock.pack-id` | `8be1eaab-ca07-4f47-9957-40d29505e320` | 空なら `resource-pack.id` を参照。実際のmcpack UUIDと一致が必要 |
| `bedrock.transfer-enabled` | `false` | パックIDが空でない場合だけ統合版の許可操作を有効にする |
| `resource-pack.enabled` | `true` | キー欠落時のコードのfallbackはfalse |
| `resource-pack.id` | `8be1eaab-ca07-4f47-9957-40d29505e320` | 非ゼロUUID |
| `resource-pack.url` | 同梱 `config.yml` の配布URL | HTTPS、userinfoなし、ASCII、2048文字以下を要求 |
| `resource-pack.sha1` | `73e0fc6020a2b160eb8d5f5b27b9e5579a773d9d` | 小文字16進40桁 |
| `resource-pack.bank-manifest-sha256` | `5aa68f33eea756ca43244751605924095dff18c5a01fd18767b3f1e51cd19506` | 小文字16進64桁。MOD側の内蔵音源との一致判定 |
| `resource-pack.prompt` | `おやさいサーバーの拡張音域リソースパックを読み込みますか？` | Java版の確認文 |
| `resource-pack.instrument-bank-event-template` | `oyasaimusic:bank/i/{instrument}/a/{anchor}` | 両置換変数必須、256文字以下、サウンドID形式 |

視聴完了率は80%固定で、`playback.view-completion-ratio` は読みません。`playback.default-mode`・`economy.points-command` も現行実装は読みません。Panのある曲は未選択なら立体音響、他は通常再生です。

### reload の範囲

設定・カタログ・ランキングJSONを読み直し、いいね／視聴／経済サービスと再生エンジンを作り直します。旧エンジンの全再生を停止し、OMMT能力を無効化します。保留中のパック待ち再生は破棄し「再読み込みのため保留中の再生を破棄しました。再度再生してください。」と通知します。GUI・コントローラーの状態を一括リセットする処理はありません。
reload時に再生セッションがある環境BGMは、旧エンジンで停止したセッションへの参照が残るため、ループONでも定期処理で自動再開しません。装填時と同じゲームモードで、持ち物に空きを作ってレコードを取り出し、再装填してトリガー条件を満たしてください。接近トリガーは範囲内を無人にしてから再入場、RSトリガーは立上がりで停止状態にしてから再度立上がりを与える方法でも再開できます。
DB接続・音源ディレクトリ・録音コマンドは作り直しません。保存先やコマンド録音の既定価格／素材変更には再起動が必要です。インポートは既定値を保存時に読むため挙動が異なります。進行中の録音は残り、保存開始前のアップロードは破棄します。保存開始後のアップロードと完了済み要求の重複抑止記録は残します。

## データと移行

| 保存場所 | 内容 |
|---|---|
| `plugins/OyasaiMusic/database.db` とSQLite補助ファイル | 曲、審査・公開・識別UUID、報酬残高・累計、いいね、お気に入り、フォロー、視聴履歴、販売、プレイリスト、再生方式、パック許可 |
| `plugins/OyasaiMusic/audio/<作者名>/<UUID>.bin` | OYMB音源。作者名の先頭の `.` を除き、パスに使えない文字を置換 |
| `plugins/OyasaiMusic/ranking_cache.json` | 前日・前週・総合の集計キャッシュ |
| `plugins/OyasaiMusic/sound-catalog.json` | 看板・試聴・カスタム音のパターン定義 |
| `plugins/OyasaiMusic/soundeffect/` | `advertise.bin`、`publish_newsong.bin`、`get_reward.bin`、`receive_likes.bin`、`send_likes.bin` |
| `plugins/OyasaiMusic/import/`・`processed/` | ファイル取込サービスの入力・処理済み。現行コマンドからの取込入口はない |
| ワールドのプレイヤー保存データ | レコードストレージ（プレイヤーPDC） |
| ワールドのジュークボックス保存データ | 装填曲・識別UUID・範囲・トリガー・ループ・ゲームモード（ブロックPDC） |
| 実際のレコードアイテム | 曲ID・識別UUID・環境BGM設定（アイテムPDC） |

移行・バックアップはDB、音源、ワールド／プレイヤーデータ、Velocityを使う場合はその許可ファイルを揃えます。稼働中のSQLite本体だけをコピーするとWAL内の確定データが欠けます。停止して揃えて保存するか、SQLiteの一貫したバックアップ方法を使ってください。

- 起動時はテーブル作成後に不足カラムを追加し、曲ごとに `record_identity` を採番します。識別カラムがない場合は `database.db.before-record-v1-<UUID>.bak` を `VACUUM INTO` で作ってから移行します。新規DBでもこのカラムは後付けのためバックアップが作られます。
- `music_feature_schema` の `limited-records` バージョンは1だけを受け付けます。未対応版では起動処理が例外で止まります。旧DBはカラム追加前に `published` 等のインデックスを作るため、カラムがない世代で移行まで到達できるとは保証されません。
- 新レコードの識別UUIDは曲ID再利用による別曲再生を防ぎます。識別UUIDのない旧レコードは、限定公開・限定品の曲へアクセスする際や定期走査で現在の曲のUUIDを付けます。旧アイテムが削除前のどの曲だったかを復元する情報はありません。旧ジュークボックス保存形式も曲IDだけで復元します。
- 音源はv1〜v4を読み、書き出しは通常v3、拡張・微分音高があればv4。古い版へ戻した際の互換性や、全世代のDB移行は未検証です。
- カタログは初回展開。特定の旧同梱カタログのSHA-1に一致すると起動時に更新します。その他の既存ファイルは残します。reloadは展開しません。欠落・不正JSON・空カタログは例外で、単なる「試聴だけ無効」にはなりません。
- 効果音は不足分だけ初回に展開。差し替えは次の通知で読みます。ランキング読込失敗は再集計、保存失敗はログだけでメモリ上の結果を残します。日付境界はサーバーの既定タイムゾーン、詳細の作成日時表示はJSTです。

## 保存・送金に失敗したとき

- 録音は音源を書いてからDBに下書きを登録します。例外時は「録音の保存中にエラーが発生しました。コンソールログを確認してください。」。通常録音は孤立ファイルや登録済み行の後始末がありません。インポートは行・音源を削除して戻そうとしますが、後始末自体の成功までは保証しません。
- BPM変更・音源差し替えは既存ファイルを直接上書きしてからDBを更新します。ファイルとDBを一括で巻き戻す処理はなく、書込途中のファイル破損・DBだけ旧値が残る可能性があります。楽曲削除はDBを先に消し、音源削除の結果を確認しません。
- 有料購入は所持金確認・Vault引落後にアイテムを渡し、販売履歴と作者残高を非同期保存します。販売DB保存が失敗しても引落・配布を戻す処理はありません。
- いいねは重複検査・曲統計・作者ポイントを同じDBトランザクションで確定します。送信者への即時入金失敗は未受取金へ退避。退避にも失敗すると`「${amount}円の入金と障害時退避に失敗しました。管理者へお知らせください。」`（`${amount}` は金額）の形式で通知します。
- 報酬受取はDB内で残高を先に消費し、その後Vault入金とポイントAPIを呼びます。失敗分だけ残高・累計を戻します。復元失敗は「失敗した報酬の残高を戻せませんでした。管理者に連絡してください。」。サーバー停止を挟んだ中断や外部APIとDBの一括確定は保証されません。
- ストレージは保存を終えてから持ち物／カーソルを変更します。読書き例外時は「ストレージを読み書きできません。保存データは保持しています。」と表示し、その画面の操作を停止します。ディスクへの永続化はサーバーのプレイヤー保存に依存します。
- ジュークボックスの登録・解除はブロックPDC更新の成否を検査します。更新失敗をユーザー用のメッセージへ変換するcatchはありません。復元できないPDC・存在しない曲・識別UUID不一致は記録を自動削除せず、操作が「レコード情報を復元中です。少し待ってから操作してください。」で止まり続ける場合があります。
- 無効化時はOMMT保存処理を最大10秒待ち、終わらなければ `DB close skipped because an OMMT import is still running` としてDBを閉じません。他の非同期DB／音源作業をすべて排出する仕組みはありません。

## 守られる範囲・制限

- 個人再生・一覧・検索・ソーシャル操作は公開状態とレコード所持を判定します。限定品の所持は持ち物と専用ストレージで、エンダーチェストや設置済みレコードは含めません。審査用試聴だけ管理権限で迂回します。
- `/mm open <ID>` は個人再生のアクセス判定前に詳細を開きます。非公開曲でも題名・作者・統計・BPM・作成日時・参考リンクは表示でき、再生の拒否は詳細情報の秘匿を保証しません。
- プレイリスト管理一覧はページ送りがなく38件まで表示し、38件で新規作成ボタンが消えます。追加先選択や共有で増えた39件目以降は管理一覧に出ません。保存件数の上限ではなく表示上の制限です。
- 個人再生は切断だけでは停止せず、再生中なら時計が進みます。終了前の再接続で残りの再生とボスバーを復元し得ますが、再生リスト・保留要求は消します。一時停止の終了タイマーは400tick（20秒相当）で、退出時に取り消し、再参加時にも再登録しません。
- 環境BGM設置は曲の存在・新レコードの識別UUID・範囲権限を確認します。公開／限定公開・個人用／限定品の再生制限は適用しません。既に設置されたBGMは、曲の非公開化や範囲権限の取り消しを逐次反映しません。
- 持ち主によるジュークボックス保護はありません。回収・交換は装填時のゲームモードで制限し、破壊で落とす経路には同モードの制限がありません。操作イベントは先行キャンセルを無視して処理し得るため、他の保護プラグインとの共存は実機で確認してください。
- 再起動・チャンク再読込で装填情報を復元しますが、再生位置・RSトグルの途中状態は保存しません。
- ソーシャル処理には自分の曲へのいいね・視聴を除外する条件がありません。参考URLの登録もURL形式や権利の審査はしません。審査の却下は公開禁止ではなく収益化判定の一部です。
- 価格 `-1` はモデル／DBでは非売品を意味しますが、GUI入力は負値を拒否します。個人用・下書き・非売品でも作者は無料取得できます。

## 他のプラグイン・外部サービス

- FAWE: 必須。コピーと回路解析。現地回路録音は新規ワールド・貼付けを行いません。
- Vault＋経済サービス: 金銭の引落・入金。無料取得は経済サービスがなくても実行できます。
- TokenManager: 有効なプラグイン名を確認し、OyasaiTokenの `OyasaiTokenService` でポイント付与・消費の保存結果を待ちます。旧コマンド送信方式は使いません。外製TokenManagerだけで同APIがなければ利用不可です。
- OyasaiUtilities: 同プラグインが有効で `oyasaiutilities-afk` metadataがtrueなら視聴を加算しません。未導入ならAFKとして扱いません。
- Floodgate: softdependの宣言のみ。Paperの統合版判定は接頭辞、VelocityはGeyser接続からUUIDとXUIDを取得します。
- OMMT: Plugin Messageによる取込・クライアント再生。バッファ失敗時はPaper再生へ戻します。旧チャット／コマンド取込はありません。
- PlayerDB: 未キャッシュのJava版ヘッドをUUIDで照会。最大同時2件、接続5秒・リクエスト8秒の期限、失敗10分キャッシュ。外部サービスの現在の稼働は未確認です。

### OMMT送信失敗の切り分け

受付上限は圧縮データ・転送データ・再構成後のOYMIそれぞれ1MiB、100,000音です。1人1転送、全体32転送、検証・保存は同時2件までです。クライアントに返すエラーコードで次を切り分けます。

| コード | 確認・対応 |
|---|---|
| `NO_PERMISSION` | `oyasaimusic.import` を確認。受付後の権限変更も対象 |
| `BUSY` | 同じ人の進行中の転送、全体の転送数、検証・保存の混雑を確認し、処理が終わってから再試行 |
| `RATE_LIMITED` | 別要求の間隔は500ms以上。連続送信を避ける |
| `OVERSIZED` | サイズ・音数・チャンク数や宣言値の範囲を確認。上限超過なら曲を短くするなどして再送 |
| `NOT_READY` / `TIMEOUT` | 受付認可は10秒、転送は10分で期限切れ。最初の受付要求からやり直す |
| `ORDER` / `MALFORMED` | 順序・長さ・ハッシュ・要求内容・形式の不整合。OMMTの送信内容と対応形式を確認 |
| `HASH` | 圧縮データの展開失敗や余分な末尾。OMMTの圧縮・送信内容を確認 |
| `IMPORT` | 再構成・ハッシュ照合・形式検証・保存などの失敗。送信データと音源・DBの保存状態を確認。この経路は例外詳細をログ出力しないため、コードだけでは原因を特定できない |

不正packetをdecodeできない場合は応答せず破棄します。無応答だけでは上記コードのどれかと断定できません。通信条件の詳細は [PROJECT.md](PROJECT.md#外部api通信境界) を参照。

### Velocity・Geyser のパック運用

Velocity中継はコードに固定された論理backend名 `main` だけが対象です。実際の非公開構成とは独立したコード上の条件です。
Velocityのプラグインデータディレクトリに以下を置きます。

| ファイル・キー | 既定・役割 |
|---|---|
| `packs/OyasaiMusic-26.2-extended.mcpack` | `pack-file` の既定名。ファイル名のみ、サブディレクトリ指定不可 |
| `bedrock-pack.properties` の `return-host` | コードの既定値を参照（ホスト名は転記しない）。統合版から戻れる接続先を設定 |
| 同 `return-port` | `19132`、有効範囲1〜65535 |
| 同 `transfer-host`／`transfer-port` | 旧キー。新キーの非空値を優先。不正値はコードの既定値へ戻す |
| `bedrock-pack-allowlist.txt` | XUIDの許可リスト。最大100,000件、読込上限4MiB |
| `bedrock-pack-identities.tsv` | UUIDとXUIDの対応。最大100,000件、読込上限8MiB |

プロパティ変更・キャッシュ済みパック差替え後はVelocityを再起動します。Paperでは `bedrock.transfer-enabled: true` とmcpackに一致するIDを設定します。Geyser全体の `force-resource-packs` はプラグインから上書きしません。コードはキャンセル時の参加を許容するためfalseにする旨をログへ出しますが、端末側の実際の参加可否は未確認です。

- Geyserイベント登録は初期化後、準備できなければ1秒後から2秒ごとに再試行。完了ログは `Subscribed Geyser pre-login pack and disconnect events.`。
- 統合版のallowは最終確認120秒、Paper保存、Velocity要求、必要なら一度だけTransferの順です。旧PaperだけのALLOWはVelocityへ自動移行しません。対象者に一度allowを再実行してもらいます。
- 再接続時の位置・ゲームモード・飛行状態の退避はメモリに60秒だけ残し、参加後10tickで復元を試みます。再起動を跨ぐ復元はありません。
- オフラインの統合版set／unsetは誰か1人が対象backendに接続している必要があり、Velocityの保存確認後にPaperを保存します。通常応答期限10秒。UUID対応がなければ旧形式UUIDの下位ビットを使う経路がありますが、未記録の連携UUIDは解決できません。
- 保存失敗でPaperとVelocityの設定が片側だけ変わる場合があります。同じ操作を再試行し、両側を確認してください。オンラインdenyの転送要求成功は保存完了メッセージの条件に含まれません。
- 許可リストは一時ファイルから置換し、UUID対応とは別々のファイルです。書込失敗はログと再試行。2ファイルとPaper DBを一括確定しません。
- `rp check` の「Geyser登録済み（端末側の受諾完了はAPIで未確認）」は現在セッションへの登録確認です。ダウンロード完了・実際の発音の証拠にはしません。
